# towel-label — 特価バスタオルの10面ラベル

2026-10-23〜24 に G1934・G1586・G1529・G1501・G1127・G1120・G1434(2色)・G1442(2色)・G1939・G1867・くろべ(画像共有61番)の
13件を作って登録し、確立した手順(2026-10-26 に G1122・G1147・G2204・画像共有147番を足して計17件)。詳しい設計・経緯・事故の記録は `011.ラベル印刷PWA/docs/特価バスタオルと納品一覧.md`。

## 何をするスキルか
- 1件 = 89×48mm の10面ラベル1枚の絵(PNG)を作る → NAS の PWA-JAN に保存 → 011(label.db)に1行足す。
- バーコード(JAN 4562210662004)は**全商品共通**。変わるのは**商品名と画像だけ**。
- 登録した名前の頭に「特価 」を付ける(PWAで「特価」で検索できる)。
- 納品のときは、PWAの「納品一覧」タブで数量を入れ、A4の一覧表と10面ラベルを印刷する。

## 新しいセッションで依頼されたら(最短)
1. このスキルと `011.ラベル印刷PWA/docs/特価バスタオルと納品一覧.md` を読む(登録済みの17件・各商品の元の写真と切り抜き値がある)
2. 「最初にまとめて聞く」の4点を聞く → 手順1〜5
3. 道具は全部 `011.ラベル印刷PWA\server\`(`towel_tools.py`・`make_towel_label.py`・`towel_register.py`)。ヘッドレスの画面確認は `011.ラベル印刷PWA\tools\`
4. 納品一覧タブの修正は `pwa/delivery.js`。直したら `python -m pytest tests -q`(58件)と `tools/check_delivery_screen.py` を通す
5. 運用者に確かめてもらうこと: **10面ラベル・A4の実際の印刷位置**(2026-10-24時点で未確認)

## 最初にまとめて聞く(途中で小出しに止めない)
1. 対象: G番号(またはURL)／画像共有の番号。複数でもよい
2. 商品名(ページの名前をもとに案を出し、確認する)
3. 画像共有の写真を使うときは、**向き**(上下反転で届くことがある。61番は180度回転が必要だった)
4. 2色あるか(ページの「●カラー:」)。**2色あるものは、色名を商品名の後ろに付けて、両方とも登録する**(例 `バスタオル(護衛艦ちくま) ホワイト`)

## 手順

### 1. 商品ページを調べる(読み取りだけ)
```
cd C:\ClaudeCode\011.ラベル印刷PWA\server
python towel_tools.py page G1434 --out C:\作業フォルダ\g1434
```
商品名(ページ)・ツイート文・カラー・画像を表示し、画像を元サイズで保存して一覧画像 `sheet.png` を作る。**sheet.png を見て、正面の写真を選ぶ。**
- 画像は `https://image1.shopserve.jp/seifukunofuji.co.jp/pic-labo/<ファイル名>`(限定なしの元サイズ。`limg/` は250pxなので使わない)
- 名前は**ファイル名が商品ごとに違う**(`g1939_main.jpg`・`nagashima_bath01.jpg`・`g1867_09.jpg` …)。名前の推測はせず、`page` の出力を使う
- 選ぶ基準: ①真正面で長方形に近い(斜めで台形に見える写真は避ける。運用者が嫌う) ②大きい(1200px > 800px) ③背景が少ない。
  商品ページの先頭の見出し付き画像(`*_main.jpg`)は、下半分に正面のタオルがあり、使える。ページに正面の写真が無いときは、正面の図(G1867)を使う
- ページに「2色」があれば、色ごとの正面写真を探す(白とブルーは別ファイル)

### 2. タオルの範囲(--crop)を決める
- **黒い縁(耳)があるタオル**: `make_towel_label.py` の自動で足りる(最も長く続く黒い縁を目印にする)
- **紺色・白・水色・縁のないタオル、背景が写る写真**: 自動は外れる(背景を含む・下端が欠ける)。`python towel_tools.py bbox 画像 --mode dark|light --ymin 380` で目安を取り、**必ず仕上がりを目で見て**微調整する
- 画像共有の実写(4096×3072)は背景(段ボール・床)が写る。範囲を手で指定する
- 上端・下端・左右が欠けていないか、背景が残っていないかを、**1枚ずつ目で確認する**(G1529で上が約15%欠けた実例)
- **写真が傾いている・背景(紺の布など)が写る写真は、長方形で切らない。「水平にして、輪郭で白抜き」する**(2026-10-26 運用者指示。データ共有147番で、傾いたまま長方形に切って2回やり直した)。商品トップ画像の白抜きと同じ考え方: 輪郭の外を純白にし、傾きは直す。
  `python towel_cutout.py 写真.jpg 出力.png` → 出力の大きさ全体を `--crop 0,0,幅,高さ` に渡す。四隅が見つからなければ止まる。出力は必ず目で見て、上下の縁に紺が残っていないか・黒い帯が欠けていないかを確かめる(`--inset` で輪郭を内側へ詰められる)。画像共有の写真は、向きは回さず**横長のまま**使う(タオルは必ず横長・絵柄の文字は横倒しでよい)

### 3. ラベルを作る
```
python make_towel_label.py G1434 --name "バスタオル(護衛艦ちくま) ホワイト" --image 画像.jpg --crop x0,y0,x1,y1 --out-dir C:\作業フォルダ
```
- ※ `-I` は付けない(同じフォルダの `label_compose.py` を読めなくなる)
- 配置は `label_compose.py` の `LAYOUT`(確定済み・下の「確定した見た目」)。値を変えるときは `LAYOUT_V1` を壊さず、`tests/` を通す
- 仕上がりを `Read` で見て、Downloads にコピーして `SendUserFile` で渡し、**名前と見た目の確認を取る**(商品名は運用者が決める。ページの表記から「海上自衛隊」を省いた形が既定)
- 商品名の括弧は**半角**に統一(運用者が全角で指定しても、既存の登録に合わせて半角にし、そう伝える)
- ページの名前の**接頭語(「ジャガード」など)は付けない**。G2204 は、ページが「ジャガードバスタオル(…35周年記念)」でも、運用者の指示で「バスタオル(護衛艦うみぎり)35周年記念」にした(2026-10-26)。迷ったら付けずに案を出し、確認を取る。登録後に名前を直すときは、ラベルの画像にも名前が入っているので、**画像を作り直して** `towel_register.py rename` を使う

### 4. 登録する(運用者が「この名前で登録」と言ってから)
```
python towel_register.py add 画像.png "バスタオル(護衛艦ちくま) ホワイト"            # 確認だけ(何も書かない)
python towel_register.py add 画像.png "バスタオル(護衛艦ちくま) ホワイト" --apply    # 書く
```
- `add` は NAS へ画像を保存 → `addProduct`(template=Blank10・JAN共通・名前=「特価 」+渡した名前)。DBのバックアップ(`label.db.bak_日時_towel`)を自動で作る
- 登録後に「一覧に1件出る」「印刷サーバーの画像が一致」まで自動で確かめる。確かめが通らなければ終了コード1
- **同じ名前が既にあれば中止**する(上書きしない)
- 名前を直す: `towel_register.py rename "特価 旧い名前" 画像.png "新しい名前" --apply`(商品IDを保つ・旧い画像は `label_png_backup_日付/` へ退避)
- 画像だけ直す: `towel_register.py replace-image "特価 バスタオル(...)" 画像.png --apply`(旧い画像は退避)

### 5. 報告する(短く)
登録した名前・商品ID・「一覧に出る/画像が一致」・「特価」を含む登録の総件数。実印刷は試していないなら、そう書く。

## 確定した見た目(2026-10-24 運用者承認)
89×48mm。余白は左4・下4・上3・右3 mm。
- 上: 商品名を**1行**で左右いっぱい(左4〜右86mm)。長い名前は文字を小さくして1行にする(最小5pt。G1529は約7pt)。**2行にしない**
- 左: タオルの画像(縦横比を保つ・縦いっぱい)。右: JANの縦バーコード(長さ28mm・倍率89%)で、**上端を画像の上端に揃える**
- バーコードの下: 赤い値札形の「特価」バッジ(白抜き)。通常価格の商品との貼り間違い防止
- 商品名と画像のかたまりは縦に中央へ置く

## 注意(実際に踏んだ罠)
- **bash のヒアドキュメントで日本語・UNCパス・`\n` を含むスクリプトを流さない**。ファイルに書いて実行する(パスの `\\` が潰れる・エスケープが落ちる・シェルが失敗する。AGENTS.md の注意どおり)
- ruff が日本語のフォルダ名で `E902 指定されたパスが見つかりません` と出すのは、**パスの文字化け(誤報)**。コードの問題ではない
- 商品ページは UTF-8。cp932 で読むと文字化けする
- `PIL` / `numpy` / `playwright` / `PyMuPDF` は使える。外部AI(Codex等)へは画像・商品名を送らない(不要)
- 本番(sfuji.f5.si)を相手にするヘッドレス検証では、**印刷・登録の POST は `route.abort()` だけ**にする。偽の応答(`route.fulfill`)にすると本物に通り抜けて、10面ラベルの用紙を実際に印刷した(2026-10-24)。送信内容の検証は node の単体テスト(`tests/test_delivery.py`)で行う
- 印刷サーバーには**取り消しの口が無い**(enqueue・status・queue だけ)。一度入ると止められない
- 011のPWAは静的ファイルで、**保存した瞬間に本番へ反映される**(再起動不要・ステージングなし)。変更前を `.bak` に残し、既存の「印刷」タブには触れない
- 白いタオルは白いラベルの地に溶ける(縁が淡い)。ブルー・水色の方が形が見える。登録は運用者が選ぶ

## 納品一覧タブ(PWA)
`https://sfuji.f5.si/label/` →「納品一覧」。ファイルは `011.ラベル印刷PWA/pwa/delivery.js`・`delivery.css`、`index.html` にタブを足してある。
1. 「特価」を含む10面ラベルを検索して追加(商品名の左にラベル画像が出る)→ 数量を入れる(＋−・直接入力。入力はこの端末に覚える)
2. **A4の一覧表**(案B・1頁7件・納品日と納品先は手書き用の空欄・頁の合計と総合計)→ プレビュー → 印刷先を選んで「印刷(A4)」。印刷先は mode=off の普通紙だけが出る(既定は PX-S887 `px-s887-plain`)
3. **10面ラベル**: 数量の数だけ10面の用紙に割り付け(列優先・最後の用紙の余りは空白・上限30枚)→「割り付けを見る」→「ラベルを印刷(10面)」。印刷先は**この端末の場所**にある10面のプリンター(印刷タブと同じ決め方・場所は右上「場所を選ぶ」)
- 印刷サーバーの許可表(`config/print_module/printer_app_matrix.csv`)で `px-s887-plain` の `label` 列を 1 にしてある(2026-10-23 承認)。この表は他セッションも編集するので、触るときは該当セルだけ
- テスト: `cd C:\ClaudeCode\011.ラベル印刷PWA && python -m pytest tests -q`(納品一覧・タオル道具・既存の印刷APIで計58件)
- 画面の確認: `python C:\ClaudeCode\011.ラベル印刷PWA\tools\check_delivery_screen.py 出力フォルダ`(本番を**読み取りだけ**で見る。非GETは遮断する)
- A4の見た目の確認: `python C:\ClaudeCode\011.ラベル印刷PWA\tools\render_delivery_pdf.py 出力フォルダ`(プレビューのHTMLを、印刷サーバーと同じ条件の `wkhtmltopdf` でPDFにして画像化する。**印刷せずに**頁数と見た目を確かめられる)

## 検証のしかた(反映系は結果を見て終える)
- 登録: `towel_register.py` の確かめ(一覧・画像の一致)。さらに `getPrinterSettings` で新しいプリンターがラベルの印刷タブに出ていないこと
- 画面: Playwright ヘッドレスで、読み取りだけ(上の注意のとおり POST は abort)
- 実印刷は、運用者が自分の手で1度押して確かめる
