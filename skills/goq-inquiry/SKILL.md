# GoQ 問い合わせの回答案

道具は `C:\ClaudeCode\103.ユーザー対応管理\goq_inquiry_cli.py`(以下 `CLI`)。

## 守ること

- **返信は送らない。** 送信の仕組みは作っていない。運用者が確認画面からコピーし、GoQ の画面で貼って送る
- GoQ の問い合わせの**詳細画面を開かない**(既読になる)。取得は一覧 API だけで足りる
- ログインは受注取得(118)と同じ既存の処理に任せる。Claude は認証情報を読まない・入力しない
- 問い合わせの本文(個人情報)を外部 AI へ送らない。回答案はこのセッションの Claude が書く
- お客様都合(注文間違い・サイズ違い・思い違い)の返品・キャンセルにはお詫び文を入れない
- 承認済みの文面にない条件(未使用に限る、期限、送料の金額など)を付け足さない
- 在庫・価格は答える直前に読み直す。報告では商品名の頭に商品コードを付ける

## 手順

1. **取得**: `python CLI fetch` → `fetched` / `needs_reply` / 新しく入った件数が出る。
   `[NG] GoQ のセッション…` は既存ログインの失敗。もう一度だけ流し、駄目なら運用者に知らせて止める
2. **材料を読む**:
   - `python CLI pending` … 返信が必要な問い合わせ。会話全文・注文内容(042 受注DB)・保存済みの案
   - `python CLI examples --limit 20` … 店舗が実際に送った返信(文体の見本)
   - **`回答集\回答ナレッジ.md`(最初に読む)** … 書き出し・返品交換・発送・商品の事実のまとめ
   - `C:\ClaudeCode\mail-skill\mail_style_guide.md` と
     `C:\ClaudeCode\900.ClaudeCode\mail-search\reply_templates.json`(承認済みの返信の型)
   - `draft_is_current: true` の件は案があるので作り直さない(運用者に頼まれたときだけ直す)
3. **調べる**(必要な件だけ):
   - 商品: `023.商品マスタDB\data\productmaster.db` の `products`(価格=楽天、`estore_price`)と `yahoo_snapshot_products`
   - 在庫: `092.受注影武者と在庫台帳\data\shadow.db` の `sku_stock`(台帳)と `mall_live_qty`(各モールの実数)
   - いずれも読み取り専用で開く(`?mode=ro`)
4. **書く**: 過去の返信に合わせる
   - 楽天: 冒頭「【制服のフジ楽天市場店】寺下です。」、末尾に楽天の定型(区切り線・rakuten@・住所)
   - Yahoo!: 冒頭「制服のフジ、寺下と申します。」(2通目以降は「寺下でございます。」)、定型の末尾は付けない
   - 返品の送り先は「〒737-0046 広島県呉市中通１丁目１番２１号 (株)制服のフジ TEL：0823-21-7731」
   - 1件ずつファイルに書いて `python CLI draft --goq <GoQ問い合わせ番号> --content-file <ファイル>` で保存
   - 調べたこと・決めたこと・運用者に決めてもらうことを `python CLI note --goq <番号> --content "..."` で残す
     (商品コード・価格・在庫とその時点、使った型や過去の返信、判断の理由)
5. **確認画面**: `python CLI render --out <scratchpad>\goq_inquiry_drafts.html` →
   Artifact で公開する。前回の画面がある場合は `url` に
   `https://claude.ai/artifact/ARrLtXmYHdrZ2XHGb52QuC` を渡して同じリンクを更新する(先に read が要る)
6. **保存(省略しない)**:
   - `python CLI export` … 案のある件・送信済みの件を `回答集\案件\<日付>_<モール>_<番号>.md` に書き出す
     (お客様の名前は書かない。git には入れない)
   - 使い回せる新しい事実・方針が出たら `回答集\回答ナレッジ.md` の該当の節へ日付と出典付きで足す
     (お客様の名前・住所・電話番号は書かない)。足したらコミットする
   - 次回 `fetch` したとき、実際に送った文面が送信済みとして入るので、もう一度 `export` する
7. **報告**: 件ごとに「モール・お客様・用件・案の要点」と、送る前に運用者が決めること
   (在庫切れの扱い、返金の範囲、返信せず対応完了にしてよいか など)を書く

## 仕組み(直すときに読む)

- `goq_inquiry_fetch.py`: `/goq21/inquiry/ajaxFetchInquiryList.php` を POST(画面が一覧表示に使うもの)。
  1件ごとに会話全文 `replies` が入っている。100件ずつ。5xx は2回まで読み直す
- `goq_inquiry.py`: 問い合わせ1件 = `inquiries` 1行。対応は `goq_inquiries`、取り込んだ発言は `goq_messages` で覚える。
  お客様の発言=`text`、店舗の返信=`response_sent`、回答案=`response_draft`。何度流しても重複しない
- 「返信が必要」= 対応完了でなく、最後の発言がお客様(GoQ の画面の判定と同じ)
- 日時: Yahoo! は `2026-10-27 07:18:46`、楽天の返信は `2026-10-28T10:13:53+09:00` で来る。どちらも日本時間の ISO にそろえる
- 注文内容は 042 の `ec_orders`、出荷済みで外れたものは `ec_orders_archive` の決めた列だけ(カード・住所は読まない)
- GoQ 自体にも「AI 返信文」機能がある(GoQ 側のサーバーへ送る方式)。こちらは使っていない
