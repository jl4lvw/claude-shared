# milifuji-invoice — ミリタリーショップFUJI 宛ての請求書メール

2026-10-21 に実際にやった流れ(7/21〜9/20分の次、9/21〜10/20分)を再現する手順。
実行は `invoice_mail.py`(このフォルダ)。**メール送信は必ず 080 の自動送信(運用者の承認つき)で行う。** Thunderbird の下書きは作らない(両方やると二重送信になる)。

## 背景(先方の依頼)

- 先方(渡辺様)は請求書を **メールで** 受け取る。宛先は **milifuji@fuji-dobuita.com**(2026-07-22 に旧 fuji@mars.plala.or.jp から変更。10/21 に LINE でも念押し)
- 請求は **毎月 20 日締め**(21 日〜翌月 20 日)。送付は締めの翌日以降。前回の送付実績: 2/21、6/20、7/22、10/1(7/21〜9/20 の 2 か月分・8月分の請求漏れのお詫び入り)、10/21(9/21〜10/20)
- Cc は kawasaki@seifukunofuji.com のみ。**本文の「Cc：」行は空欄**。AI の断り書きは入れない。署名は寺下さんの定型を本文末尾に入れる
- 先方への LINE 返信は不要(2026-10-21 運用者)

## 手順

```bash
S=C:/ClaudeCode/.claude/skills/milifuji-invoice/invoice_mail.py
```

1. **PDF を出す**(期間を省略すると直近の 20 日締めまでを自動で決める。違うときは `--start 2026-09-21 --end 2026-10-20`)
   ```bash
   python $S pdf
   ```
   コンパスの請求書 API(`/api/external/invoice/pdf`・LAN 内・キーは `013.CONPHAS-PWA/server/external_secrets.json`)で出し、**Downloads と NAS の 999.一時ファイルの両方**へ置く。明細行数が 0 なら送らず、運用者に聞く。
2. **PDF を目で確認する**(PNG にして Read)。請求日・件名・金額(税率別)・明細。「前回までの残金」欄が空欄でも、これまでは**そのまま送っている**(売掛残との差 222,089 円は 2026-10-02 に保留・11月に再検討。送付とは別扱い。メモリ `project_milifuji_receivable_gap_hold_until_nov`)
3. **アーティファクトで送信予定を見せて承認を得る**(`/mail-send` の Step 1〜2)。To・Cc・件名・添付・本文全文・請求金額の要点・生成日時(JST)。PDF の気になる点(残金欄の空欄など)は上部に注意として書く。**承認が出るまで次へ進まない**
4. **送信前チェック(省略不可)**
   - テンプレ・前回比較: `017.Tシャツなどの注文/mail_history/` の前回の請求書メールと本文を比べる。差は「期間」「Cc 行が空欄」「AI 断り書きなし」だけのはず
   - DeepSeek レビュー: `python C:/ClaudeCode/.claude/tools/deepseek_coder.py --role reviewer <プロンプトファイル>`。プロンプトの冒頭に「既定事項(指摘不要)」(全角＠・【秘密事項】/To/Cc 行・署名の記号・AI 断り書きなし)を入れる。本文だけ送る(PDF の中身・金額は送らない)。指摘は採否を判断する(携帯番号の署名・結語の重なりは既存運用で不採用)
   - 実行した時刻(JST)を控える。次の手順で記録に入れる
5. **自動送信を依頼する**(080 が EML を検査し、見張り役が運用者に承認を求める)
   ```bash
   python $S submit --work-dir <スクラッチ> --four-stage-at 2026-10-21T17:23:00+09:00 --deepseek-at 2026-10-21T17:24:39+09:00
   ```
   `--dry-run` を付けると zip を作るだけで提出しない。チェックの時刻は**実際に行った時刻**を入れる(手で偽らない)。
6. **承認を待つ**: 運用者へ「承認の画面で請求書 PDF の画像を確かめて承認してください」と案内する。添付つきは承認の画面で画像を確かめたときだけ承認できる(LINE の「実行」・電話では中止だけ)。Claude が承認を代わりに行うことは絶対にしない。
   「押したら知らせて」と頼まず、裏で結果を待つ(完了通知が来る):
   ```bash
   python $S wait <job_id> --minutes 30      # run_in_background で実行
   ```
7. **結果を確認して報告する**: `smtp_accepted` かつ `copy=OK` で送信完了。`expired`(承認の期限 30 分)・`rejected`・`failed` は送っていない。再送するときは新しい job_id で依頼し直す。`unknown` は再送せず送信済みフォルダを確認する。

## 守ること

- 送信は 080 経由の 1 回だけ。Thunderbird の下書きも作ったら、運用者に**送信せず閉じる**よう伝える(10/21 はこの二重の恐れがあった)
- 承認依頼は 19:00〜翌 9:00 でも出てよいか、運用者の運用に従う(LINE グループへの報告とは別)
- 請求書の金額・金額の差の議論をメール本文に書かない
- 宛先アドレスが変わったと先方から来たら、`invoice_mail.py` の `TO` と本スキルの背景を更新する
- スキルを直したら `skill_scope.py check` が exit 0 か確認し、`/g-ul` で共有へ反映する
