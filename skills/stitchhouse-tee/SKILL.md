# /stitchhouse-tee — ステッチハウス無地Tシャツ手配の変換

ステッチハウス(寺下さん経由)から次の形式で依頼が来る。これを TOMS の CSV に変換し、`/toms-web` に渡す。

```
ブラック: Mサイズ50枚 / Lサイズ70枚
ネイビー: LLサイズ20枚
オリーブ: 3Lサイズ10枚
グレー: LLサイズ10枚
```

## 固定の変換（2026-10-17 ユーザー決定）

| 依頼文の表現 | 読み替え | TOMS 00300 カラーコード |
|---|---|---|
| ブラック | ブラック | 005 |
| ネイビー | ネイビー | 031 |
| ホワイト | ホワイト | 001 |
| **オリーブ** | **必ずアーミーグリーン** | 037 |
| **グレー** | **必ずダークグレー** | 187 |

- 品番は **00300 固定**（4.4ozドライTシャツ ACT。ユーザー確認済「300でOK」）。
- サイズコード: S01 M02 L03 LL04 3L06 4L09 5L47（`017.Tシャツなどの注文/toms_size_codes.json`）。
- 表にない色（例: ピンク）が来たら**推測せず停止**し、ユーザーに確認する。TOMS 画面で色名を確認して `toms_color_codes.json` に追記する。
- 黒/白の取り違え事故あり（001=白 / 005=黒）。変換結果の表を必ず見せる。

## 手順

1. **質問は最初にまとめて**（AskUserQuestion）: 納品先（送り先がステッチハウスで TOMS の納品先に登録があるか／セブンエス経由か）・運送会社・出荷日。未確認事項を操作の途中で聞かない。
2. 依頼文を UTF-8 のテキストにして保存し、変換する:
   ```
   python ".claude/skills/stitchhouse-tee/scripts/parse_order.py" <依頼文.txt> --out "017.Tシャツなどの注文/toms_csv/YYYYMMDD_ステッチハウス無地T_TOMS.csv"
   ```
   色・サイズごとの読み替え結果と合計枚数が表示される。**依頼文の合計と一致するか確認**。
3. CSV の**フルパスを表示**し、`~/Downloads` にもコピー。
4. `/toms-web` を、この CSV で実行（確認画面で止まる・確定はユーザー）。
5. 確定・検証後、入荷登録の申請は納品先がセブンエスの場合のみ。`toms_order` の `python cli.py arrival N` で申請まで自動（貼り付け不要・確定は運用者が ECM で PIN 承認。toms-web の該当節）。

6. **依頼元チャットへの完了通知（申請）**（2026-10-17 追加。TOMS 確定・検証が済んでから）:
   1. 通知本文を作る（事務的・端的。ユーザー決定の形。納品先は「ステッチハウス直送」、運送会社は「ヤマト運輸」と省略せず書く）:
      ```
      無地Tシャツ手配完了しました
      受注番号：#<8桁>
      数量：<枚数>枚
      納品先：ステッチハウス直送
      出荷：<M/D>(<曜>) ヤマト運輸
      ```
      URL・@メンションは入れられない（入れると 400）。1000 字以内。**Downloads と NAS（`\\192.168.1.50\共有スペース\寺下\999.一時ファイル\`）の両方に置く**（テキスト成果物のルール）。
   2. 申請する: `python 094.Chrome自動操作\notify_client.py submit <本文.txt> --ref <090受付番号> --toms-order <8桁>`
      - 090 受付番号は、マイタスクのメモにある「090受付 #N」。無ければユーザーに聞く（最初の質問に含める）。マイタスク id での指定は未対応。
      - 宛先（依頼元の LINE グループ）は 090 が ref から決める。こちらからは指定できない。
      - 結果は承認待ち（pending_approval）。**LINE へは送られない**。
   3. ユーザーに「090 の PWA（https://line-agent.sfuji.f5.si/ →『完了通知の承認待ち』）で本文を見て『承認して送信する』を押してください」と伝える。TK は承認も送信もしない。
   4. 承認後は `notify_client.py show <request_id>` で `sent` になったか確認。同じ ref への再通知は 409。
7. マイタスク（`/t`）の完了は、ユーザーの承認を得てから A に note 追記 + done を依頼する（A 経由）。フラグ解除（clear）は指示があるときだけ。

## 備考・注意

- CSV の備考は「ステッチハウス」、お客様注文NOは `fuji`（既存CSVに合わせた）。
- 依頼の原本は 050 マイタスク「AI依頼」にあることがある（`/t`。TK では A 経由で読む）。タスクのフラグ解除・完了はユーザー承認後。
- 発注履歴(history.csv)・Sheets への記録は tshirt-order の工程チェックに従う。
