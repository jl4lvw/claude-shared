# label-rebuild — 10面ラベルを写真とイラストから組み直す

2026-11-13 に「JMSDF ドライパーカー」(JAN 4562210665746・商品ID 2082)で確立した手順。
データ共有 #277(今の札の写真)と #278(発注の指示書の .ai)から作り直し、登録し、実際に印刷して収まることを運用者が確認した。

- 部品と検査: `C:\ClaudeCode\011.ラベル印刷PWA\server\label_compose.py`(試験 `tests/test_label_compose.py`)
- 実例(写して使う): `011.ラベル印刷PWA\server\compose_examples\jmsdf_dry_parka.py`
- 新規登録は `ai_label_import.py register`、差し替えは `label_compose.py replace`

## 絶対の決まり
- **横の画像(登録する 89×48mm)の上側 = 縦の札の右端に、2mm 以上の余白を残す**(2026-11-13 運用者決定)。
  端まで絵があると、印刷で隣のシートへずれて印刷される。JMSDF ドライパーカーでは右袖がはみ出して起きた。3mm 空けたら収まった。
  `label_compose.py check` が 2mm 未満を不合格にする。ほかの辺も 1.5mm 未満は注意が出る。
- 元のファイル(写真・.ai)は読むだけ。変更・削除しない。
- 登録・差し替えは、アーティファクトで見本と登録内容を見せて承認をもらってから。

## 最初にまとめて聞く(依頼に書いてあれば聞かない)
1. 手本(今の札の写真)と元のイラスト: データ共有の番号、NAS のパス、または渡されたファイル
2. 商品名(PWA の検索用。今の札の題名から案を出す)
3. JAN(写真のバーコードの数字を読んで確認する。読めないときだけ聞く)
4. 新規登録か、登録済みの差し替えか(DB を JAN で引けば分かることが多い。分かれば聞かない)

## 手順
作業フォルダは scratchpad(またはその日の `C:\tmp-ai\label-日付`)。データ共有は `/img` の `get` で取り出す。

### 1. 調べる(読むだけ)
- 写真を `Read` で見て、札の向き(縦か横か)・題名・絵の配置・バーコードの数字・下の文字を書き出す。
  札の写真はたいてい縦。縦 48×89mm として、各要素の位置を写真の高さ・幅に対する割合で測る。
- .ai を `python server\ai_label_import.py analyze <.ai> --out-dir <作業>\analyze` で描き、`cells_sheet.png` を見る。
  面付けでなく指示書のことが多い(面の数が10にならない)。使う絵の場所を `page.get_pixmap(dpi=300, clip=...)` で切り出して確かめる。
- 図形の一覧(`page.get_drawings()`)を色ごとに数え、使う絵の範囲(pt)を決める。**隣の別の絵(前向きの絵など)が範囲に入らないか**必ず確かめる
  (11/13 は前向きのパーカーの袖が入り、右端に見えていた)。`pick_drawings` は範囲に丸ごと入る図形だけを拾う。
- DB で同じ JAN の登録を探す: `products` 表(`jan`・`name`・`png`・`active`・`mensu`)。

### 2. 組み立てる
- `compose_examples/jmsdf_dry_parka.py` を作業フォルダへ写し、範囲・位置・文字・フォントを替える。部品は `label_compose` から使う:
  `pick_drawings`(線と塗りを拾う)・`place_matrix` と `redraw`(拡大して置く)・`draw_ean13`(バーコード)・
  `mask_edge(pg, "right", 3.0)`(右端の余白)・`to_landscape`(600dpi で描いて左回りに回す)・`check_image`。
- 描き直しはベクターのまま行う(画像に描いてから拡大しない)。白い塗りでページの外まで覆わないと、端に1画素の線が残る(`mask_edge` はページの外まで塗る)。
- フォント: 明朝の太い題名は `HGRME.TTC`(HG明朝E)、JAN の数字は `OCRB.TTF`、英字は `arial.ttf`・`ariblk.ttf`。
- 手本の札にあって .ai に無いもの(11/13 は袖の白い柄)は描かず、見本で違いとして伝える。
- 作ったら `Read` で縦の見本を見て、手本と並べて確かめる。

### 3. 検査する(読むだけ)
```
python server\label_compose.py check <作業>\label.png --jan <JAN>
```
`ok: true`(大きさ 2102×1134px・上側の余白 2mm 以上・バーコードが読める)でなければ直す。余白(mm)は結果の `margins_mm`。

### 4. アーティファクトで見せる → 承認
手本の写真・作った札(縦)・登録する画像(横)・登録内容の表(商品名・JAN・面数10・Blank10・カテゴリ・画像ファイル名・重複の有無・余白)・手本との違いを1ページにまとめる。
画像は縮めて JPEG の data URI で埋め込む。登録する画像は `C:\Users\user\Downloads\` にも写す。
直しの指示(例 11/13「上の文字をもっと大きく」)が来たら、組み立てを直して同じアーティファクトを出し直す。

### 5. 登録する(承認後)
- **新規**: `python server\ai_label_import.py register <png> --name "<名前>" --jan <JAN> --category "10面ラベル"`(下見)→ `--apply`。
  `ok: true`・`listed: 1`・`image_matches: true` のときだけ成功。DB の控えは自動で `label.db.bak_日時_aiimport`。
- **差し替え**(同じ名前・JAN の有効な行がある): `python server\label_compose.py replace <png> --name "<名前>" --jan <JAN>`(下見)→ `--apply`。
  DB の行はそのままで NAS の PNG だけを替える。前の画像は `server\replaced_png\` に控える。`nas_matches`・`image_matches` が両方 true で成功。
- 使ったデータ共有には `/img` の `used` で印を付ける。

### 6. 報告する
商品名・商品ID・JAN・「一覧に出る/画像が一致/バーコードが読める/上側の余白 ○mm」。**実際の印刷は未確認**と書き、PWA から1枚試し印刷してもらう。

## 注意
- bash のヒアドキュメントに日本語・UNC パス・エスケープを書かない。組み立てスクリプトは Write で書いて実行する。
- ruff が日本語フォルダ名で `E902` を出すのは誤報。
- 11/13 の実例の数値: パーカー高さ 50.5mm・帽子中心 x=29.5mm・題名 19pt/17pt・右端の白 3mm・バーコード 0.30mm/モジュール。
