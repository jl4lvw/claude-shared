# stock-alert — 在庫切れ通知 → 商品状態の表示 → 在庫復活

作業フォルダ: `C:\ClaudeCode\.claude\skills\stock-alert`。ツール: `stock_alert_artifact.py`(読み取り専用)。

**2026-10-15 寺下さん決定**: 在庫切れの通知は、その品番の在庫状態を**商品画像・商品名・品番とともにアーティファクトで表示**する。
在庫を復活できるものは「Reply needed」として、寺下さんがすぐ在庫を変更できる情報を出す。
在庫を復活できるかは**寺下さんが現物を確認して数を決める**(データだけでは決めない)。数が決まったら、**承認後に Claude が `goq-stock-set` で変更**する。

## いつ使うか

- **mc の結果に、次の通知が出たとき(自動)**: Eストアー「在庫切れのお知らせ(品番)」(`sp@estore.co.jp`)/ GoQ「連携在庫マイナス」(`stock2-notification@goqsystem.com`)
  - mc の「候補」に Eストアーの在庫切れが出る。GoQ の通知は mc では除外されるので、`stock_notices.py` で見る
- 「在庫切れ確認」「在庫復活」と言われたとき

## 手順

### 1. 要対応を集めて、アーティファクトを作る(読み取りだけ)

```bash
python C:/ClaudeCode/.claude/skills/stock-alert/stock_alert_artifact.py --days 3 --out C:/ClaudeCode/.mail_drafts/stock_alert.html
python C:/ClaudeCode/.claude/skills/stock-alert/stock_alert_artifact.py --code G0884 --out C:/ClaudeCode/.mail_drafts/stock_alert.html   # この品番だけ
```

- 内部で `900.ClaudeCode/mail-search/scripts/stock_notices.py --json` を呼び、**023の現在庫を引き直して、まだ0以下(または不明)のものだけ**を残す
- 商品画像・Eストア在庫は 026 の商品一覧(`http://localhost:8294/api/items/export`)から取る。画像が無ければ「画像なし」と出す
- カードの内容: 商品画像 / 商品名 / 品番(対象サイズ) / 種別(連携在庫マイナス・在庫切れ) / 在庫(023) / Eストア在庫 / 通知回数・最新時刻 / 該当する受注 / 商品ページ

### 2. アーティファクトを公開して、返信を待つ

`Artifact` ツールで `stock_alert.html` を公開する(`icon`: `list` など)。**見出しは「在庫切れ 要対応(Reply needed)」**。
寺下さんの返信の形: `G0884 5個` / `G2222 見送り`。数が書かれていない・曖昧なものは聞き返す(推測で数を決めない)。

### 2.5 現物確認の紙(A4 PDF)を出す(寺下さんが「印刷したい」「現物確認表」と言ったとき)

2026-10-16 寺下さん決定の形(案A)。**この形を変えない**(変えるときは見本をアーティファクトで見せて承認を得る)。

```bash
C:/Users/user/AppData/Local/Programs/Python/Python312/python.exe C:/ClaudeCode/.claude/skills/stock-alert/stock_check_sheet.py --out-dir C:/tmp-ai/stockcheck --copy
# 品番を指定: --code G2210 --code U0147 ...(無指定なら通知の要対応を拾う)
```

- 商品ごとに「写真・商品名・品番」+ バリエーション(サイズ)ごとの行。列は **サイズ・種類 / Eストア在庫 / 現物の数(手書き)** の3つだけ
- **Eストア在庫が0のセルだけ薄い赤**。「受注あり」「通知」の印・楽天在庫列・見送り欄は出さない(寺下さん指示)
- **1商品(バリエーション全体)はページをまたがない。** 入りきらなければ商品ごと次のページへ送る。高さはブラウザで実測して割り付ける(推測しない)
- Eストアの見せかけの行(「以前のサイズデータ」「備考欄に記載」。在庫9995等)は載せない
- 出力は PDF(A4・PDF内ページ数が想定と違えば exit 1)・印刷用HTML・アーティファクト用HTML。`--copy` で **Downloads と NAS(`\192.168.1.50\共有スペース\寺下\999.一時ファイル`)の両方**へコピーし、サイズ一致まで確認する
- **印刷を頼まれたら、このPCの標準プリンターで印刷する**(2026-10-16 寺下さん指示。プリンター名は聞かない)。標準プリンターは `Get-CimInstance Win32_Printer | ? Default` で確かめて報告に書く。手順: PDF を PyMuPDF で 200dpi の PNG にし、`powershell -NoProfile -ExecutionPolicy Bypass -File C:/ClaudeCode/.claude/skills/stock-alert/print_pages.ps1 -Files "p1.png,p2.png"` で送る(`-Preview` を付けると印刷せずに処理だけ確認できる。ファイルはカンマ区切りの1つの文字列で渡す)。送信後に `Get-PrintJob` でジョブが出たことを確かめる。**頼まれていないのに印刷しない**
- 在庫・写真は実行時に読み直した値。作成時刻が見出しに入る。PDF を開き直したときは時刻を見て古い紙を使わない
- 寺下さんが紙に書いた数は、`品番 サイズ ○個` の形で返信してもらい、次の手順 3 へ進む(サイズ別の数は、サイズごとに確認表へ並べる)

### 3. 数が決まったら、変更の一覧を出して承認を得る

`goq-stock-set` の手順に従う(商品名特定 → 確認表 → 実行。**確認表の承認前に変更しない**):
- 一覧の項目: 品番(商品名を括弧書き)・現在の連携在庫・変更後の数・対象モール
- 承認後に実行し、**変更後に読み直して**数が反映されたことを確認してから報告する
- 文脈台帳に承認(OK)と、完了後の検証(VERIFY)を記録する

## 守ること・罠

- **このスキルのツールは読み取り専用。** 在庫の変更は必ず `goq-stock-set` で、承認後に行う
- **「連携在庫マイナス(-1)」は売り越しではない。** この店は実在庫より少なく(5個程度の余裕を残して)連携在庫を登録している。
  -1 は「登録した連携在庫を使い切った」で、**実物はまだ残っていることが多い**。ただし連携が尽きるとモールで売れなくなるので、入れ直しの合図
- **ベアなど、ネット未登録の店頭在庫がある商品は、実質在庫無制限。** データ上の0を理由に「足りない」と判断しない
- 同じ商品が `U0143<>5L`(GoQ)と `U0143`(Eストア)で別表記で届く。ツールは親コード(`G2123`)にまとめる
- 在庫が引けないとき(023のAPI停止など)は「不明」と出し、**要対応に倒す**(見落とすより、出しすぎる方が安全)
- 026のEストア一覧は、価格などの更新が数分遅れることがある(在庫切れの直後は、Eストア在庫が古いことがある)
- 受注のあるマイナスは、先に「商品が実際にあるか」を確認する(寺下さんの現物確認)
