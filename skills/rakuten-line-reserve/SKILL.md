# /rakuten-line-reserve — 楽天LINE の配信予約(依頼の確認 → 承認 → 予約 → 確認 → 知らせ)

2026-10-24 運用者決定で作成。**LINE で完了を知らせたところまでで完了**。

```
① 依頼を読む       LINE「楽天メルマガ配信」の「【○○配信希望】の【楽天LINE】作成しました」(090 の受信記録)
② 下書きを読む     LINE Official Account Manager の「下書き」一覧(読むだけ)→ ID・配信日時・配信先・本文の先頭
②' カードの検査    カードの商品リンクが正しいか・品切れでないか(lineoa_reserve cards → check_mail_links.py)
③ 照合だけ実行     lineoa_reserve check(何も押さない)
④ 申請             lineoa_reserve enqueue → 見張り役が承認の画面で承認を求める
⑤ 予約(自動)      承認されたら見張り役が run → 照合 →「配信予約」→ 詳細画面で「配信予約中」を確かめる
⑥ 知らせ           /line-notify の手順で「楽天メルマガ配信」へ(承認の画面で承認を受けてから)
```

## 🚨 絶対ルール

1. **押すのは「配信予約」とその確認だけ。** 今すぐ配信・テスト配信・下書き保存・削除・編集内容の変更はしない(道具が通信ごと止める)。
2. **承認は承認の画面だけ**(チャットで承認を求めない)。Claude が Chrome で「配信予約」を押すことはしない(自動操作は承認された run だけ)。
3. **下書きの中身(本文・画像・配信日時・配信先)は直さない。** 照合が合わなければ止めて、違いを担当者に伝わる形で報告する(直すのは担当者)。
4. 配信先は「すべての友だち」だけ扱う(絞り込みは未対応・止まる)。配信日時まで 10 分を切っていたら押さない。
5. **ログインは運用者だけ。** 切れていたら `needs_human` で止まるので、`login` の窓で運用者にログインしてもらう(Claude はパスワードを入れない)。
6. 失敗は自動で出し直さない。原因を報告してユーザーに聞く。
7. 対象のアカウントは「制服のフジ楽天市場店」(`@072pxwvf`)だけ(`lineoa_reserve/config.py` の `ACCOUNTS`)。Yahoo!店・本店の LINE は対象外。

## 手順

### ① 依頼を読む
090 の受信記録を**読み取り専用**で開き、「楽天メルマガ配信」グループの直近の発言から【楽天LINE】の依頼を探す
(`090.LINE業務指示エージェント/data/line_agent.db` の `line_messages`。グループ ID は会話に書かない。`received_at` はミリ秒)。
配信希望の日時(例「本日19時30分配信希望」)を控える。【Yahoo! LINE】は別アカウントなので対象外。

### ② 下書きを読む(Claude in Chrome・読むだけ)
`https://manager.line.biz/account/@072pxwvf/broadcast` →「下書き」→ 依頼の時刻ごろに更新された行(更新者は詳細画面の「最終更新者」)。
詳細画面 `…/broadcast/<ID>` で ステータス(下書き)・配信日時・ターゲット を、編集画面 `…/broadcast/edit/<ID>` で本文(テキストの吹き出し)を読む。**編集画面では何も押さない**(開いただけでは保存されない)。
- 本文の先頭(text_head)は、**絵文字を含まない 10 文字以上**を選ぶ(絵文字は画像で表示され、照合で見つからないことがある)。
- 配信日時が依頼の希望と違う・空(今すぐ配信)なら、止めて担当者に確認(直さない)。
- 今月の無料メッセージ数(一覧の上)も控える。友だち数(約 406 人)を足して 5,000 を超えるなら報告する。

### ②' カードの中身を検査する(2026-10-24 運用者指示・必須)
カード型メッセージの各カードについて、**商品へのリンクが間違っていないか・リンク先の商品が品切れでないか**を確かめる。
```
cd C:\ClaudeCode\900.ClaudeCode
python -m lineoa_reserve.cli cards <ID> --out "000.tmp\lineoa_<日付>"
python "..\.claude\skills\rakuten-merumaga\scripts\check_mail_links.py" "000.tmp\lineoa_<日付>\cards_tag.txt" --json "000.tmp\lineoa_<日付>\cards_check.json"
```
- `cards` は専用ブラウザ(ログイン済み)で詳細画面を開き、管理画面が読み込む配信のデータからカードの文字とリンクを取り出す(読むだけ)。リンクの説明には、カードの最後の文字(商品名など)を使う。
- 検査はメルマガと同じ道具(RMS API で商品の有無・表示・商品名・在庫、ほかは HTTP)。終了コード 0=問題なし / 1=警告 / 2=全商品が販売不可。
- **報告はカードの番号つきの表**にする(番号・カードの文字・リンク先・結果)。品切れ・一部品切れ・リンク切れ・違う商品の疑いは、担当者に伝わる形で書く。
- 警告の読み方(2026-10-24 実例): カードの「トマホークT」と RMS の「TOMAHAWK」はカタカナと英字の違いで一致度が下がるだけ(同じ商品)。特設会場の「本日20時スタート♪」とページ名の不一致は案内文なので問題なし。商品ページの品番(URL の g番号)とカードの商品名が合っているかは自分の目でも確かめる。
- エラー(全商品が販売不可)・リンク切れ・品切れがあれば、**申請(④)の前に止めて**ユーザーに続行か中止かを聞く(下書きは直さない)。

### ③ 照合だけ実行(何も押さない)
```
cd C:\ClaudeCode\900.ClaudeCode
python -m lineoa_reserve.cli check <ID> --send-at "YYYY-MM-DD HH:MM" --text-head "<本文の先頭>"
```
- `ok` … 次へ。`mismatch` … 違い(`diffs`)を報告して止める。`needs_human` … ⑤の「ログイン」へ。

### ④ 申請
```
python -m lineoa_reserve.cli enqueue <ID> --send-at "YYYY-MM-DD HH:MM" --text-head "<本文の先頭>" --purpose "<日付>の楽天LINE(<内容>)を<時刻>に配信予約するため"
```
- 見張り役が承認の画面で承認を求める。結果は `python -m lineoa_reserve.cli show <申請番号>` が `ok` / `failed` / `mismatch` / `needs_human` / `not_approved` になるまで裏で待つ(30 秒間隔のループを `run_in_background`)。
- 運用者には「承認の画面で承認してください。結果は自動で見ています」とだけ伝える。

### ⑤ 結果の確認
- `ok`: 押した後に詳細画面を読み直し、ステータスに「予約」が入り、配信日時が申請どおり。`shot` に画面の写し。
- `failed`: `detail` と `guard`(止めた・通した通信)をそのまま報告。**初回の実行で、画面の読み込みに必要な書き込みを止めて失敗した可能性がある**ときは、`guard` の block を見て運用者に相談する(勝手に許可を広げない)。
- 実行の後、Chrome で「配信予約中」の一覧も読んで、その ID・日時があることを確かめる(読むだけ)。
- **ログイン**(初回・切れたとき): `python -m lineoa_reserve.cli login` で専用ブラウザ(`a_browser_data\.profile_lineoa`)が開く。運用者が LINE ヤフー Business ID でログインし、アカウントリストが出たら自動で閉じる(15 分待つ)。ふだんの Chrome のログインとは別。

### ⑥ LINE で知らせる(`/line-notify` の手順 1〜4)

2. **カードごとの確認(N枚)**(No|カード|リンク先|在庫|結果): ②'の `cards.json` と検査結果から 1 枚 1 行。リンク先は商品なら G番号、ほかは「マラソン特設会場」「クーポン」「店内検索」「店舗トップ」など。widths `[80, 460, 260, 150, 170]`

  `python -m lineoa_reserve.report --store rakuten --cards <cards.json> --check <cards_check.json> --send-at "YYYY-MM-DD HH:MM" --friends 406 --reserved --out <フォルダ> [--accept <確かめて問題なしとした警告の URL> ...]`
  → `body.txt` と `spec.json`(OK でないカードがあれば「気づいた点」の欄が付く)。実例: `900.ClaudeCode/000.tmp/lineoa_20261024/spec2.json`。

## 2026-10-26 受付 #32 で分かったこと(日時が空の下書き・画像だけの下書き・日時の変更)

- **090 が断った依頼もこのスキルで受ける。** 090 は「楽天LINEを確認して配信して」を一斉配信として断って終わる(受付 #32「未完終了」)。運用者に「対応して」と言われたら、ここの手順で予約まで進める。
- **一覧は台本で読める**(Chrome のログインが切れていても、専用ブラウザで読める): `python ..\.claude\skills\rakuten-line-reserve\scripts\list_drafts.py`(900.ClaudeCode で)。下書き・配信予約中・配信済みの最新 1 件を、ID・配信日時・届いた人数・吹き出しの種類つきで出す。専用ブラウザもログインが切れていたら `cli login` を裏で起動し、運用者にログインを頼む。
- **配信日時が空(今すぐ配信)の下書き**: 止めて運用者に聞く。候補の時刻は**これまでの配信時刻から Claude が出す**(10 月は 18:30 が多い)。運用者が「Claude が入れる」を選んだときだけ、`scripts/set_schedule.py <ID> YYYY/MM/DD HH:MM` で入れて確かめ(保存しない)、`--save` で「下書き保存」だけ押す。台本は「予約・すべての友だち・日時・UTC +9:00」が画面で合わないと保存しない。承認は台帳(ctx)に `OK` で残す。
- **予約の日時を変えるとき**: 配信予約中の配信に `set_schedule.py --save` を使うと下書きに戻る(=前の予約は消える)。そのあと ③照合 → ④申請(目的の文を変えて新しい申請にする)→ 承認でやり直す。古い日時の知らせを申請済みなら、承認の画面で中止してもらい、文と画像を作り直して申請し直す。
- **カードでなく画像 1 枚(RICH・imagemap)の下書き**: `cli cards` は空を返す。リンクは配信のデータの `balloons[].messageObject.actions[].linkUri` にある。`cards.json` を `[{"no":1,"texts":["<altText>"],"uris":["<リンク>"]}]` の形で書き、`cards_tag.txt` を作って `check_mail_links.py` に通す。照合の本文の先頭(text_head)は、その `altText`(例「東京・神楽坂「MADE IN KURE」出店のお知らせ」)でよかった。
- 知らせの表は、カードが無いときは「商品リンク(0点)」の行を消し、「画像のリンク先(○○)が開ける」にする。日時を Claude が入れたときは、本文にその理由を 1 行書く(「下書きに配信日時が入っていなかったため、本日 18:30 で予約しました。」)。実例: `900.ClaudeCode/000.tmp/lineoa_20261026/report/`。
