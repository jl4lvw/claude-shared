# ctx — 文脈台帳

## 何のためにあるか

コンテキスト圧縮は「何をやっていたか」を要約として残すが、**「何をやってはいけないか」「どこまで許可されたか」を落とす**。この非対称性が事故を生む。

| 層 | 対象 | 圧縮耐性 |
|---|---|---|
| CLAUDE.md / rules | 恒久ルール | ◎ 毎回再注入される |
| memory | 恒久的な好み・事実 | ◎ 索引は毎回再注入 |
| **ctx (本スキル)** | **セッション内だけ有効な揮発性情報** | **◎ 圧縮直後に自動再注入** |
| handoff | セッション跨ぎの引継ぎ文書 | — 手動保存 |

memory は「恒久ルール」、handoff は「セッション跨ぎ」を担当しており、**同一セッション内の揮発性情報だけが誰も見ていなかった**。そこを埋めるのが本スキル。

## 台帳の場所（推測禁止）

`C:\ClaudeCode\.ctx\CTX_<session_id>.md`

**session_id は system prompt の scratchpad ディレクトリ名と同一。**

```
scratchpad: ...\Temp\claude\C--ClaudeCode\f8a6d9e2-d62d-4915-9e1b-c1d41de930d5\scratchpad
                                          ^^^^^^^^^^ これが session_id
→ 台帳: C:\ClaudeCode\.ctx\CTX_f8a6d9e2-d62d-4915-9e1b-c1d41de930d5.md
```

ここから組み立てる。**glob で `.ctx/CTX_*.md` を探して当てにいくのは禁止**（他セッションの台帳を掴む。`C:/tmp-ai` の汎用ファイル名を別セッションと共有して Codex が誤った内容をレビューした事故と同じ形になる）。

組み立てたパスが実在しなければフックが動いていない。**黙って手動運用に落とさず、必ずユーザーに報告する**（保全できている前提で作業を続けるのが一番危ない）。

## 注入の見え方（静かであることが仕様）

`additionalContext` はユーザーの画面にも出るため、**出力するのは圧縮直後と異常時だけ**。

| 状況 | 表示 |
|---|---|
| 通常のターン（制約があってもなくても） | **何も出ない** |
| **圧縮直後の1ターンだけ** | 警告行＋`[ctx] 🚫 … \| ✅ … \| ⚙️ …` の1行 |
| 異常時 | `[ctx] ⚠️ …`（degraded・圧縮の有無に関わらず） |

**なぜ毎ターン出さなくても保護が薄くならないか**: 注入した行は**会話履歴の一部として残る**ので、圧縮のたびに1回出せば、その内容は次の圧縮まで会話に居続ける。次の圧縮でまた注入されるので鎖は切れない。逆に圧縮が起きていないターンでは会話そのものに制約が残っているので、注入する意味がない。

初版は台帳が空でもパス行を毎ターン出していて、ユーザーから「毎回出てくる」と指摘を受けた（2026-07-30）。パスは scratchpad から導けるので通知は不要だった。**この静かさを壊す変更をしてはいけない。**

### フックが効いているかのセルフチェック

台帳ファイルが作られない / `⚠️` 付きの degraded 表示が出た場合はこれを確認する（**注入が出ないこと自体は正常** — 上の「注入の見え方」参照）:

```bash
python -c "import json,sys; sys.stdout.reconfigure(encoding='utf-8'); h=json.load(open(r'C:/ClaudeCode/.claude/settings.local.json',encoding='utf-8'))['hooks']; print('UserPromptSubmit:', [x['command'] for x in h.get('UserPromptSubmit',[{}])[0].get('hooks',[])]); print('PostCompact:', [e.get('matcher') for e in h.get('PostCompact',[])])"
```

```bash
type "%LOCALAPPDATA%\ClaudeCodeCtx\ctx_hook.log"
```

**他端末での注意**: `settings.local.json` は git 未追跡で `/g-ul` の同期対象にも入っていない。一方 `.claude/hooks/` と `.claude/skills/` は同期される。つまり**他の PC ではフック本体とスキル定義だけ届いて、フック登録が無い**状態になる。その端末では `[ctx]` の注入行が一切出ないので、上のセルフチェックで登録の有無を確認し、無ければ `settings.local.json` の `hooks` に `UserPromptSubmit`（3つ目として追記）と `PostCompact`（`auto` / `manual` の2エントリ）を足す。

### 異常時の表示

`[ctx] ⚠️ ...` で始まる注入が出たら台帳は**無効**。以下のどれか:

| 表示 | 意味 |
|---|---|
| セッション識別子が取得できない | `session_id` も `transcript_path` も payload に無い（通常は起こらない）。共有ファイルへ書くと別セッションに制約が混入するので、あえて何も書かない（fail closed） |
| 台帳を作成できませんでした | `.ctx` への書込権限やパスの問題 |
| フックが異常終了しました | 例外。`ctx_hook.log` に型と内容が残る |

## 6枠

| TAG | 枠 | 何を書くか | 圧縮直後の自動注入 |
|---|---|---|---|
| `LIMIT` | 🚫制約 | このセッション限定の禁止・限定（「触るのは検証SKU G2168 だけ」） | **される** |
| `OK` | ✅承認 | ユーザーから得た許可。**対象を必ず書く** | **される** |
| `STATE` | ⚙️状態 | 起動中の staging / タスク / 使用中の一時ファイル名 | **される** |
| `VAL` | 🔢値 | SKU・ポート・ID・実験で判った境界値 | されない |
| `DEAD` | 💀失敗 | 試して失敗した方法＋症状 | されない |
| `VERIFY` | 🔬検証 | 何が検証済み / 未検証 | されない |

自動注入は事故に直結する上3枠のみ（上限20項目 / 1500文字・1行に詰める）。下3枠は圧縮後に `/ctx` で台帳を読めば足りる。

## 行フォーマット（append-only）

```
14:32 LIMIT 触るのは検証SKU G2168 のみ
14:35 OK    本番適用OK — 対象: 022 fbm-sync の数量更新のみ
14:36 STATE staging 8296 起動中
14:52 DROP  STATE staging 8296 起動中
15:01 COMPACT auto
```

- **既存行は絶対に書き換えない。** 無効化は `DROP <TAG> <本文>` を追記する（元の行と TAG・本文が完全一致していること）
- 上書きを許すと「いつ何が有効だったか」が追えなくなり、事故の事後追跡ができない
- **`DROP` は時系列で効く** — その時点までに有効な同一行のうち**最後の1件だけ**を取り消す。だから `STATE staging 8296 起動中` → `DROP` → 再起動して**同じ本文で** `STATE` を追記、で正しく復活する（グローバル完全一致だと再追加分まで永久に消えていた）
- 同じ本文が2件ある状態で `DROP` を1回打つと、消えるのは1件だけ。2件消すには `DROP` を2回打つ
- `COMPACT` 行は `PostCompact` フックが自動で打つ。手で書かない

## 追記トリガー（最重要・これを守らないとスキルが無意味になる）

**ユーザーに `/ctx` を打たせるのではなく、以下が発生した瞬間に自分で追記する。**

| 発生したこと | 追記する枠 |
|---|---|
| ユーザーが「〜するな」「〜だけ使え」「今日は〜まで」と言った | `LIMIT` |
| ユーザーが本番適用・デプロイ・書込実行を承認した | `OK`（**対象を書く**。「OK」だけでは後で範囲が判らない） |
| staging を起動した / 一時ファイルを作った / タスクを止めた | `STATE`（解除時は `DROP`） |
| 試して失敗した（HTTP 4xx、import エラー、想定と違う挙動） | `DEAD`（症状も書く） |
| 検証が通った / 飛ばした | `VERIFY` |
| 実験で境界値・実SKU・ポートが判明した | `VAL` |

追記は Bash から1行で行う（ヘルパ経由。直接 `>>` でファイルに追記してもよいが時刻は必ず実時刻）:

```bash
python -c "import sys; sys.path.insert(0, r'C:/ClaudeCode/.claude/hooks'); import ctx_ledger as L; L.append(L.ledger_path('<session_id>'), 'LIMIT', '触るのは検証SKU G2168 のみ')"
```

`<session_id>` は scratchpad ディレクトリ名。`L.ledger_path()` がパスを組み立てる。

## 書いてはいけないもの

- **PIN・パスワード・API キー・トークンの値そのもの。** 「PIN はユーザーに口頭確認済」のような**事実だけ**書く
- 顧客個人情報・社内 DB 接続文字列も同様
- 伏字化は**追記時と注入時の両方**で走る（`api_key=xxx` / `パスワードは xxx` / `Bearer xxx` / 接続文字列の `user:pass@` を `***` にする）。ただし表記の揺れは必ず抜けるので、**保険を頼りにしない**。台帳は平文ファイルで、`/ctx` では直接 Read される

## サブコマンド

| 引数 | 動作 |
|---|---|
| （なし） | 台帳を Read して6枠を一覧表示し、**認識を宣言**する（圧縮直後の自己点検） |
| `add` | 未記録のものを拾って追記する |
| `ready` | 未記録がないか確認して追記し、「圧縮して安全」と告げて `/compact` をコピー用ブロックで出す |
| `clear` | 対象を確認して `DROP` を追記する |

### `/ctx`（引数なし）— 自己点検

1. scratchpad のセッションIDから台帳パスを組み立てる
2. Read で台帳を読む
3. 6枠を一覧表示（`DROP` された行は除く）
4. **認識を宣言する** — 「守るべき制約 / 得た承認とその対象 / 起動中プロセス」を明示し、「この認識で進めます」と言う

宣言はユーザーが誤りに気づける最後の防壁なので、省略しない。

### `/ctx ready`（圧縮前確認）

`/ctx` と同じ点検をした上で、末尾に**それだけが入った単独のコードブロック**で `/compact` を出す:

````markdown
保全しました。抜けが無ければ圧縮して大丈夫です。

```
/compact
```
````

**厳守**: 説明文と同じコードブロックに入れない。コピーボタンはブロック全体をコピーするため、混ぜるとユーザーが範囲選択するハメになる。

**`/compact` は代行できない。** 組み込みコマンドなので、実行はユーザーの手に残る。押すよう促すところまでが本スキルの限界。

## 圧縮直後の挙動（自動）

`PostCompact` フックが台帳へ `COMPACT auto|manual` を追記し、次ターンの注入に

```
⚠️ 直前にコンテキスト圧縮が起きました (計 N 回 / 最新 HH:MM auto)。
```

が付く。これを見たら **`/ctx` を待たずに自分から台帳を Read して自己点検し、認識を宣言してから作業を続ける**。警告は圧縮回数が増えた回だけ出る（毎ターン出すと無視されるため）。

**注意**: 台帳が空のセッションでは圧縮が起きても制約行は出ない（保全すべきものが無いので正しい）。警告行だけが1回出る。

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `.claude/hooks/ctx_ledger.py` | パス決定・追記・パース・伏字化の共通ロジック |
| `.claude/hooks/ctx_inject.py` | `UserPromptSubmit`: 圧縮直後に制約・承認・状態を注入 |
| `.claude/hooks/ctx_compact_mark.py` | `PostCompact`: 圧縮印を追記 |

フックは例外を全部飲んで `exit 0` する（本流を絶対に止めない）。ただし**静かには壊れない** — 異常時は `ctx_inject.py` が `[ctx] ⚠️ ...` の degraded 表示を注入し、`%LOCALAPPDATA%\ClaudeCodeCtx\ctx_hook.log` に理由が残る。注入行が完全に消えた場合はフック自体が未登録（上のセルフチェック参照）。

## handoff との関係

| | handoff | ctx |
|---|---|---|
| 寿命 | セッション**間** | セッション**内** |
| 書込 | 手動・一気に | 随時・1行ずつ・自動 |
| 読者 | 次セッションの Claude と人間 | 同一セッションの圧縮後の自分 |

`/handoff save` の時は台帳の `DEAD`（失敗した試行）と `VERIFY`（検証状態）を読んで handoff に取り込む。既存 handoff テンプレにこの2枠は無いので、ここで埋まる。

## 注意

- 台帳は `.gitignore` 対象（`.ctx/`）。なお `.handoff/` は実際には ignore されていないので「handoff と同じ」ではない
- 時刻は必ず実時刻。`ctx_ledger.append` が `datetime.now()` で入れるので手入力しない
- 同一作業を2セッションで進めると台帳は分裂する（handoff と同じ制約）。セッション分離を崩すほうが危険なので許容する
- `/compact` の抑止・遅延・タイミング制御はできない。auto-compact は予告なく来る前提の設計
