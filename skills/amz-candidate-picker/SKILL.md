# amz-candidate-picker — 候補セレクター(検索+チェックボックス)アーティファクト

商品候補のリスト(Amazon未登録候補の洗い出し結果など)を、検索で絞り込みながら
チェックボックスで選び、選択結果を Claude が読み戻せる形にする Artifact を作る手順。

2026-09-10〜11 の「ワッペン候補67件」選定で確立した。「一つ一つチャットで絞り込むのは
無駄なので、アーティファクトでまとめて指示する」という運用に応える。**同じものを毎回
同じ品質で再現するため、依頼文もHTMLもClaudeが都度書き直さず、この skill のテンプレート
+ ビルドスクリプトを使う。**

## いつ使うか

- Amazon未登録商品の洗い出し等で、候補が数十件規模になり、チャットで1件ずつ
  「これは対象?」とやり取りするのが非効率な場合
- ユーザーが「検索して」「絞り込んで」「まとめて選びたい」と言った場合
- 過去に一度この skill で作ったセレクターと**同じ見た目・同じ操作性**が必要な場合
  (毎回ゼロから設計し直すと、ボタンの位置や検索の挙動が微妙に変わってユーザーが迷う)

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `template_candidate_picker.html` | プレースホルダ入りのHTML本体。**手で書き換えない**(汎用テンプレートとして維持する) |
| `build_candidate_picker.py` | JSON配列 + パラメータ からプレースホルダを埋めた完成HTMLを吐き出すビルドスクリプト |

## 手順

### Step 1: 候補データをJSON配列にする

各要素は以下のスキーマ(キー名固定):

```json
{
  "g": "G2139",
  "sku": "G2139",
  "name": "PVCワッペン ( 潜水艦せきりゅう )",
  "price": 990,
  "stock": 90,
  "status": "public"
}
```

- `g`: 行を一意に識別する文字列。この business では G番号を使うのでキー名は `g` 固定で良い
  (別の識別子体系でも `g` にそのまま入れてよい。表示ラベルは変えられないので `商品コード` 等に
  読み替えて運用する)
- `stock`: 在庫数(int)。親SKU等で子側管理のため不明な場合は `null`
- `status`: `"public"` (公開) か `"hidden"` (非公開) の2値。それ以外は非公開フィルタに掛からない

商品マスタDB(023 `productmaster.db`)・Amazon在庫DB(022 `amzinv.db`)等から抽出したデータを、
一度この形に整形してから渡す。整形スクリプトは対象カテゴリごとに毎回変わってよい
(ここは skill 化しない。skill 化するのは「整形後のデータを渡した先」のUI部分)。

### Step 2: ビルドスクリプトで完成HTMLを作る

```bash
python C:/ClaudeCode/.claude/skills/amz-candidate-picker/build_candidate_picker.py \
  --input candidates.json \
  --output out.html \
  --title "◯◯候補セレクター" \
  --eyebrow "Amazon未登録候補 · ◯◯限定 N件" \
  --subtitle "検索で絞り込み、行をクリック(またはチェックボックス)で選択してください。選択内容は下部に一覧され、自動保存されます。" \
  --footer "データは生成日時のスナップショット。登録前に現況の再確認が必要です。" \
  --slug amz_◯◯_picker \
  --search-placeholder "G番号・SKU・商品名で検索 (例: ◯◯)"
```

- `--slug` は他の候補セレクターと衝突しないユニークな値にする(DB保存先が
  `candidate_picker/<slug>/selection` になるため、同じ slug を使い回すと前回の選択が
  残ったまま出てくる。**カテゴリが変わったら slug も変える**)
- `--title` / `--eyebrow` / `--subtitle` / `--footer` / `--search-placeholder` は
  毎回の対象に合わせて書き換える。**HTMLの構造・CSS・JSは一切変えない**(そこが
  「全く同じものを作る」の core)

### Step 3: Artifact として publish する

```
Artifact({
  file_path: "<Step2の出力パス>",
  title: "<--titleと同じ>",
  description: "<一文で要約>",
  capabilities: {"db": {}},
  favicon: "🎖️"   // カテゴリに応じて変えてよい。一度決めたら同じ artifact への再publishでは省略する
})
```

新規カテゴリ = 新規 Artifact(新しいURL)。既存の候補セレクターの中身を更新したい場合のみ
`url` を指定して同じ Artifact を再publishする。

### Step 4: ユーザーの選択を読み戻す

ユーザーが「選び終わった」と言ったら:

```
Artifact({
  action: "read_db",
  url: "<publishしたURL>",
  db_op: "get",
  collection: "candidate_picker/<slug>",
  doc_id: "selection"
})
```

`{"selected": ["G2139", "G2179", ...], "updated_at": "..."}` が返る。この配列を
「ユーザーの指示」として扱い、次の作業(引き継ぎファイルへの反映、登録セッションへの
引き渡し等)を進める。

## 画面の仕様(テンプレートが実装済み・変更不要)

- 検索欄: G番号・SKU・商品名を横断する部分一致(大小文字区別なし)
- クイックフィルタ: すべて / 在庫あり / 在庫0 / 非公開 の4chip(排他選択)
- テーブル: チェックボックス列 + G番号 + SKU + 商品名 + 価格 + 在庫バッジ
  - 行クリックでもチェックボックスクリックでもトグルする(どちらか一方だけ実装すると
    「行をクリックしたら選択されるようにして」という要望を満たせない)
  - 在庫は 0/正の数/null(親SKU)の3パターンをバッジで色分け表示
- 選択中の一覧: 画面下部に固定表示。チップ形式で選択済みG番号を表示し、chip内の×で
  個別解除もできる
- 選択は `db` capability で自動保存(400ms デバウンス)。ページを開き直しても復元される
- 「G番号をコピー」ボタンでクリップボードに改行区切りでコピー可能

## 既知の落とし穴(修正済み・テンプレートに反映済み)

**外側のツールバーと、テーブルヘッダーの2つを別々にpage-stickyさせると、
オフセットがズレて前の行が透けて見える。**

初回実装(2026-09-10)では、`.toolbar` を `position: sticky; top: 0`、
`thead th` を `position: sticky; top: 54px`(ツールバーの高さを決め打ち)にしていた。
ツールバーの実際の高さが、検索欄・チップ・件数表示の折り返し具合によって54pxからズレると、
スクロール時にテーブルヘッダーの上にスクロール済みの行が一瞬透けて見える不具合が
ユーザー側の画面で実際に発生した(スクリーンショットで報告あり)。

**対処**: テーブルを独立したスクロール領域にする(`.table-scroll { overflow:auto;
max-height: min(58vh, 520px); }`)。`thead th` の sticky はこの領域内の `top: 0` にする。
これによりページ全体のツールバーの高さと無関係になり、マジックナンバーの
オフセット合わせが不要になる。**このテンプレートを流用する限り再発しない。**
もし将来この部分を書き換える場合は、ページ全体スクロールに対する複数要素の
sticky offset 決め打ちを避けること。

## 対象データの由来(参考: G番号突合の方法)

ワッペン候補67件は、023商品マスタDB(`products`テーブル、`estore_status in
('public','hidden')`)と022 Amazon在庫DB(`inventory_items`テーブル)を、両者のSKU文字列に
含まれるG番号(正規表現 `G\d{3,4}`、先頭ゼロを正規化して比較)で突合し、Eストア側にのみ
存在するG番号を「Amazon未登録候補」とすることで作成した。この方法は
`900.ClaudeCode/amz_unregistered_queue/wappen_candidates_20260910.json` の
`method` フィールドに記録されている。同じ方法を他カテゴリにも使い回せる
(商品名に含むキーワードでの絞り込み条件を変えるだけでよい)。

**注意**: 文字列突合であり意味確認はしていない。過去に登録廃止した商品・意図的に
未出店の商品も区別なく候補に含まれうる。
