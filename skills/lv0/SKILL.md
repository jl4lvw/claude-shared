# lv0 — Codex に実装を任せる（Claude のトークンを最小にする委譲レーン）

**目的**: Claude の消費を減らし、Codex（ChatGPT サブスク枠・実費 0）に負担を寄せる。
Claude がやるのは **仕様を書く → 承認を取る → 1 コマンド起動 → レポートを読む** の 4 つだけ。
準備・Codex 実行・検査・失敗時の出し直し・差分の集計は `cgd_lv0_auto.py` が回す。

> 旧手順（Claude が prepare / run / diff / 検証を 1 つずつ叩く）は `cgd/reference/lv0_manual_steps.md` に残してある。
> ドライバが使えないときの逃げ道。通常は使わない。

## 使う / 使わない

| 使う | 使わない（Claude が直接直す） |
|---|---|
| 新規モジュール・複数ファイルの実装・テストの量産 | 1 回の変更が **約 200 行未満**（依頼の往復が勝つ。実測の損益分岐） |
| 1 回の委譲が約 200 行を超える | 設計判断が重い変更（DB 設計・状態管理・セキュリティ） |
| 既存コードに沿った繰り返し実装 | 本番 DB・外部 API への書込（サンドボックスはネット無し） |
| | 作業フォルダを 1 つに絞れない変更 |

## `--review lv3a`（レベル0A / Lv0A）

Lv0 の実装に、**レビューの取りまとめと 🔴 の自動修正**まで足した版。「レベル0A」「Lv0A」と言われたとき、または想定が **+100 行以上**でレビュー全文を Claude が読まずに済ませたいときに使う。通常の「レベル0」は従来どおり `--review none` / `--review deepseek`（3A・5A と同じく、A は名指しされたときだけ）。

- **流れ**: Codex 実装 → 機械検査（失敗は出し直し）→ **Lv3A**（Codex・DeepSeek の 2社×2視点。取りまとめは Codex）で差分レビュー → 採用された 🔴 があれば **Codex が自動修正 1 周** → 軽い再レビュー → 短いレポート。Claude がやるのは、レポートと 🔴 の原文突合だけ
- **実装の前に Lv3A の `plan` を自動で 1 回回す**（鍵の未設定などで「実装したのにレビューできない」を防ぐ）。失敗したら実装を始めず exit 1
- **組** `--roster lv3|lv7|lv8`（既定 lv3）: 関数間の整合性・状態管理が論点なら `lv7`、批評も欲しければ `lv8`。lv7/lv8 は Qwen も送信先に加わる。`--no-ds` / `--no-qwen` で外せる。**再レビューは組にかかわらず軽い構成**（lv3・DeepSeek なし）
- 小さい差分（`--review-min-plus` 未満。既定 100 行）はレビューを省略し、レポートに省略と出る（常にレビューするなら `--review-min-plus 0`）
- 差分が大きいときは 50,000 バイト以下の束（最大 3 束）に分けて回す。入りきらないファイルは「未レビュー」になり要判断
- 🔴 の自動修正は最大 1 周（`--no-autofix` で止められる）。再レビューにも 🔴 が残れば 2 周目は回さず要判断
- `--redact` は使えない。秘匿候補で止まった差分は、内容を確認して `/lv3a` を `--redact` 付きで個別に回す
- **費用の目安（玩具・実測 2026-09-21）**: +55 行の実装（Codex 約 1.7 万 tokens）に、Lv3A（lv3）＋自動修正＋再レビューで Codex 7 回 約 5 万 tokens・DeepSeek ¥0.4（全体で約 5 分半）。lv7（自動修正なし）は Codex 3 回 約 1.8 万 tokens・DeepSeek ¥0.4・Qwen ¥0.7（約 2 分 20 秒）。束が増えれば概ね比例する

手順は下の 1〜5 と同じで、`plan` と `run` に `--review lv3a [--roster lv7|lv8] [--no-ds] [--no-qwen] [--no-autofix]` を足す。違いは 3 点:
1. **承認表（手順 2）**: `plan --review lv3a` の出力に Lv3A の点検（組・週枠・送信先）が続く。送信先に Lv3A のレビュー先（Codex・DeepSeek、lv7/lv8 は Qwen も）を明記して承認を取る
2. **レポート（手順 4）**: 末尾に「Lv3A レビュー」の節（25 行以内）が付く。上の「変更」は**最初の実装だけ**で、自動修正で増減した分は節の「自動修正の変更」に出る。🔴 は、節の「記録」の下の `b<N>/<run>/*.md`（`integration.md` と各レビュアーの生ログ）を grep して、題名・対応案と食い違わないかだけ確かめる（全体は読み直さない）
3. **終了コード 21 = 実装 OK・レビューで要判断**（🔴 が残る・未レビューがある・レビュー失敗・自動修正の停止）。理由は節の「要判断の理由」に出る。**統合者が見送った 🔴 も数える**（Lv5A と同じ。最終判断は人）。実例（lv7）: Qwen が「静的な列名にプレースホルダが無い」を 🔴 としたが、統合者が「プレースホルダは値の束縛用」と見送り、生ログの grep で妥当と確かめられた

```bash
python "C:/ClaudeCode/.claude/tools/cgd_lv0_auto.py" plan --workdir "<作業フォルダ>" --checks "<検査定義>" --review lv3a [--roster lv7]
python "C:/ClaudeCode/.claude/tools/cgd_lv0_auto.py" run --workdir "<作業フォルダ>" --checks "<検査定義>" --spec "<仕様>" --effort medium --review lv3a [--roster lv7]
```

## 手順

### 1. 準備（Claude）
1. `date +%Y%m%d_%H%M%S` は**不要**（RUN はドライバが決める）。
2. **作業フォルダを 1 つ決める**（git リポジトリの内側のサブフォルダ。最上位は拒否される）。`.hq/board` で同じフォルダを触る他セッションが無いか確認。
3. **仕様ファイルを書く**（`C:/tmp-ai/cgd_lv0_spec_<名前>.txt`・UTF-8・Write ツール）: 目的 / 変更してよいファイル / 変えてはいけないもの / 受け入れ条件。
   **設計は仕様書（docs/spec.md 等）に書き、依頼文は「節番号を読んで実装」だけにする**（Codex は作業フォルダの中を自分で読める。共通の約束事はエンジンとドライバが付ける）。
4. **検査定義 JSON を書く**（**作業フォルダの外**・例 `C:/tmp-ai/cgd_lv0_checks_<名前>.json`）。書式は `checks.example.json`。
   - `frozen`: 出し直しで**変更・削除させない**ファイル（テスト等）。もとからあるテストは初回から守られ、Codex が初回に書いたテストは出し直しから守られる
   - 検査の型: `js-syntax`（変更した .js/.mjs に node --check）/ `lf`（CR 検査）/ `ruff` / `cmd`（任意コマンド。python は自動で解決）/ `e2e`（Playwright。アプリを検査用に起動して回す）
   - アプリの起動は `serve`。**検査用の一時データで動かす**（`{tmp}` を使う）。本番 DB・本番ポートは指定しない
   - **e2e があると、ドライバが「e2e の書き方の約束」（`e2e_contract.md`）を仕様に自動で足す**。Codex がスマホ幅の Playwright スクリプトを書き、機械が回して、失敗は Codex に戻る

### 2. 承認（Claude → ユーザー）
```bash
python "C:/ClaudeCode/.claude/tools/cgd_lv0_auto.py" plan --workdir "<作業フォルダ>" --checks "<検査定義>" [--review deepseek]
```
出力（作業フォルダの点検・**秘密情報らしいファイル**・検査コマンド一覧・凍結・出し直しの上限・**送信先**）をそのまま表にして
**AskUserQuestion で承認**（外部送信の秘匿チェックを兼ねる。承認前に run しない）。
- `plan` が exit 1（作業フォルダ不正・Codex CLI 無し）なら中止。利用枠が 80% 以上でも代替手順（DS/Qwen）へ
- **秘密情報らしいファイル（特に業務 DB。072 なら `server/data/`）が出たら、仕様にも「<パス> は開かない」と明記する**（依頼文では止めているが仕組みでは止まらない）
- 想定 +50 行以上なら `--review deepseek` を付けるか判断（DeepSeek は中国本土サーバ。承認表の送信先に書く）

### 3. 実行（バックグラウンド・待つだけ）
```bash
python "C:/ClaudeCode/.claude/tools/cgd_lv0_auto.py" run --workdir "<作業フォルダ>" --checks "<検査定義>" --spec "<仕様>" --effort medium [--max-fix-rounds 2] [--review deepseek]
```
- **Bash の `run_in_background: true` で起動**し、終了通知を待つ。**途中で様子を見に行かない**（待つ間は Claude も Codex も枠を使わない）
- 推論強度は Claude が自動選択（既定 `medium`、ロジックが込み入るなら `high`）。出し直しは同じ強度
- exit 0 = 全検査合格 / 3 = Codex 失敗・変更なし / 10 = 検査が通らない・停滞 / 11 = 利用枠で停止 / 1 = 前段で停止（他セッションが触った等） / 21 = 実装 OK・レビューで要判断（`--review lv3a` のみ）

### 4. レポートを読む（Claude）
出力の末尾がレポート（約 30〜50 行）。**読むのはこれだけ**。`changes.patch` や stderr を主 context に読み込まない。
| 状態 | やること |
|---|---|
| OK | 変更一覧・スクリーンショット（パスが出る）を 1〜2 枚見る。画面は要点だけブラウザで確認。反映は各プロジェクトの手順で |
| 実装OK・レビューで要判断（21） | 節の「要判断の理由」と 🔴 を読み、🔴 は生ログを grep して原文突合する（見送られた 🔴 も対象）。見送りが妥当ならそのまま最終まとめへ（最終判断は人）。直すなら小さく直して `check` で再検査、大きければ仕様を直して新しい run |
| 検査が通らない / 停滞 | 失敗の抜粋が小さければ Claude が直して `cgd_lv0_auto.py check --workdir … --checks …` で再検査。大きければ仕様を直して新しい run |
| Codex 失敗・変更なし | 最終報告（質問）に答えて仕様を直し、新しい run。連続するなら Lv0 が向かない兆候 → Lv2 を提案 |
| 利用枠で停止 | 代替手順（`cgd/reference/lv0_ds_qwen_fallback.md`）か、枠が戻るまで待つ |

### 5. 最終まとめ
レポートの数字をそのまま使う: 作業フォルダ・変更件数と +/- 行・Codex の周数/秒/tokens/週の利用枠・検査結果・凍結違反・DeepSeek の結果・Claude が直した箇所（Lv0A のときは Lv3A の 🔴/🟠/🟡・自動修正・費用も）。

## ガードレール（ドライバとエンジンが機械で守る）
- 作業フォルダの外に書かない・秘密情報らしいファイルは写さない・`git diff` を使わず写しと比べる・同じ RUN の再実行を拒否
- 検査には鍵・トークン・パスワードらしい名前の環境変数を渡さない
- 出し直しは最大 2 周（既定）・週の利用枠 80% で停止・失敗の中身が変わらなければ停止
- 凍結ファイルの変更は写しから戻し、レポートに違反として載る
- **Claude が裏で延々書き直すフォールバックは取らない**（Lv0 の意義が消える）。直すのは「小さな残り」だけ
