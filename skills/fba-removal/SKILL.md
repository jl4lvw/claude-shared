# /fba-removal — FBA 在庫を本店へ取り戻す

2026-11-09 にパーカー3柄(G2041・G2048・G2124)の 12 SKU・22 点で確立した手順。

## 前提

- **返送依頼は SP-API では作れない。** セラーセントラルの画面で作る
- **作成した返送依頼は取り消せない。** 「確認」→確定は**運用者が自分で押す**(Claude は押さない。運用者がはっきり「確定まで進めて」と言ったときだけ例外)
- 出荷まで通常 10〜14 営業日。10〜12 月は最大 30 日
- 返送中・後も **FBA の SKU を自社出荷(FBM)に切り替えない**(FBA 登録 SKU を自社出荷へ戻すのは禁止)。自社出荷は別の `-LCL-` SKU がある商品だけ
- **戻った商品をすぐ 092 の在庫へ戻さない。** 不良品の可能性などで戻すことがある。在庫に戻すかは運用者が決める(Claude から在庫登録を提案・実行しない)

## 手順

### 1. 対象と数を出す(読み取りだけ)

```bash
python C:/ClaudeCode/.claude/skills/fba-removal/list_removal.py <親SKU-parent または 子SKU> ...
```

- 親 SKU はその子すべて、それ以外は SKU そのもの。返送数 = 販売可能数
- 「注意: 引当・入出荷作業中・販売不可」が出たら運用者に伝える(引当は注文の分なので返送しない。販売不可も返送するかは聞く)
- 「見つからない指定」があれば exit 1。SKU を確かめ直す
- 最終全件同期の時刻(UTC)が古ければ、画面の数を正とする(手順 3 で照合する)
- 報告の商品名には必ず G 番号を付ける

### 2. 戻し方を確認する(クリック形式)

- **返送依頼(推奨)**: 手数料が一番安い。以下の手順
- マルチチャネル出荷(`900.ClaudeCode/mail-search/scripts/fba_mcf_ship.py`): 早いがお客様宛てと同じ手数料で高い。運用者が選んだときだけ

### 3. セラーセントラルで作成画面まで進める

**この端末の Chrome だけを使う。** 毎回 `list_connected_browsers` で `inUse` かつ `onThisComputer: true` を確かめる。無ければ操作しない。

1. `https://sellercentral.amazon.co.jp/inventoryplanning/manageinventoryhealth`(上のメニュー「Amazonの在庫管理」= FBA在庫管理)を開く
   - 「全在庫の管理」(/myinventory)の一括操作には返送が**無い**。`/fba/inventory` や `/recommendations/inventory/removal` は「見つかりません」
2. 「SKU、ASIN、または商品詳細で検索」に親 SKU から `-parent` を取った前方部分(例 `FJ-G2041-PK-SMKT`)を入れて検索
   - カンマ区切りの複数検索は 0 件になる。**1 柄ずつ検索する**
   - URL でも検索できる: `...manageinventoryhealth?sort_column=product_details&sort_direction=asc&sort_column_sub=msku&search=<語>`
   - 検索結果に別の柄(同じ前方部分の別商品)が混ざっていないか確かめる
3. 見出し行のチェックボックスで全選択。**選択は検索をまたいで残る**ので、次の柄を検索してまた全選択 → 下の帯の「N個の商品を選択済み」が対象の SKU 数と合うか確かめる
   - 画面がスクロールしているとき座標でクリックすると商品リンクを押して別タブが開くことがある。開いたら閉じる
4. 「グループアクションを選択」→「返送/所有権の放棄依頼を作成」。**新しいタブ**(`/recoveryui/removal-order/create?...`)で開く
5. 返送方法は「**発送先住所**」を選ぶ。送り先が本店(〒737-0046 呉市中通1-1-21 制服のフジ)か確かめる。違えば止めて運用者に聞く
6. 数量欄は影 DOM(`kat-input`)の中で、アクセシビリティの一覧に出ない。Tab で移ると「×(行を削除)」ボタンへ行くので**Tab で移らない**。次のように JS で欄を集め、1 つずつ focus してから文字を打つ(値を JS で直接入れない):

```js
function all(r,s,o=[]){r.querySelectorAll(s).forEach(e=>o.push(e));r.querySelectorAll('*').forEach(e=>{if(e.shadowRoot)all(e.shadowRoot,s,o)});return o}
window.__q = all(document,'input').filter(i=>!i.disabled && i.type==='number');
window.__q[0].scrollIntoView({block:'center'}); window.__q[0].focus();
```

   - 欄は画面の行の順(手順 1 の出力と同じ SKU 順か、画面の本文で確かめる)。販売不可の欄は N/A で入力できない
7. 入れ終わったら照合する: 各欄の値(`window.__q.map(i=>i.value)`)が各行の「Nユニット中」と合い、画面の「合計：SKU n個 販売可能：m点」が手順 1 の合計と一致すること
8. 一番下までスクロールして「確認」の手前で止める。最初の在庫一覧のタブは閉じ、作成画面のタブは運用者のために開いたままにする

### 4. 運用者に渡す

- 表(親 SKU・子 SKU・返送数・合計)と、送り先・返送方法・取り消せないこと・日数・Amazon 側が在庫切れになることを書く
- 押す手順: 「確認」→ 次の画面で合計と送り先を確かめて確定
- 進み具合は同じ画面の「返送/所有権の放棄レポートを表示」で見られる
- 確定したら、記憶に課題メモ(対象・点数・日付・届いた後の扱い)を残す。届いた後の扱い(092 へ戻すか)は運用者の判断を待つ
