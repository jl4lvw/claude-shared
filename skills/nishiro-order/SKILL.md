## 1. 発注書を確認する

1. 複合機の受信履歴: `017.Tシャツなどの注文/fax_sent_check.py` の `fetch_rows()`(読み取り専用・履歴閲覧用アカウントを keyring から使う)。ジョブ種別「Windows (SMB)」・宛先「FAX転送」の行が**受信FAX**(送信ではない)。時刻が西ロジのメールの頃のものを探す
2. 受信FAXのPDFは NAS `\\192.168.1.50\共有スペース\FAX\FAX転送_YYYYMMDDHHMMSS.pdf`(開始時刻と一致)。**フォルダの件数が多く `ls` は遅い**ので、PowerShell の `DirectoryInfo.EnumerateFileSystemInfos()` で日付で絞る
3. PDF は Read で読める(1枚が画像。向きが横なので、読み取りづらいときは回して見る)
4. **メール本文とFAXを突き合わせる**。11/9 は、メールに「Tシャツ20枚は M・L・LL・3L を5枚ずつ、色はすべて黒」とあり、FAXの発注書には色・サイズが無かった。運用者に聞いた内訳(黒と白)がメールと食い違っていたので、メールに合わせて直した。**メールの追記を読み落とさない**
5. 発注書の合計(個数・金額)と、あとで積む予約の合計を一致させる(11/9: 139個・104,110円)

## 2. JAN から G番号を当てはめる

当たる順番(11/9 実績):

1. pickorder のマスタ(`http://127.0.0.1:8087/gasapi?action=getMaster`。JAN・商品名・所在・`productCode`)
2. 023 の `yahoo_snapshot_products.jan`(`C:\ClaudeCode\023.商品マスタDB\data\productmaster.db` を読み取り専用で)
3. SKUDB(`\\192.168.1.50\共有スペース\寺下\992.ピッキングリスト作成用データ連携\SKUDB.csv`・cp932)で商品名・G番号を**全件**検索する(**検索結果を `head` で切ると既存行を見落とす**。11/9 は G2017 が既にあるのを見落としかけた)

番号が無い新商品は **Google スプレッドシート「フジ商品番号DB」**(`/rakuten-new-item` と同じ・記憶 `reference_g_number_sheet_fuji_db`)から取る。該当する商品名があれば採用、無ければ商品名が空の先頭の行で採番(=シートへの書き込みなので運用者の承認が要る。読み取りは `C:\Users\user\.gcp\tshirt-order-sa.json`)。同じ商品の番号が別に無いかを必ず見る。

11/9 の実績: G2255=クリアファイル(IC4×大和ミュージアム)・G2256=ハンドタオル(同)・G2257=マグカップ(IC4デザイン×大和ミュージアム)を 280〜282 行目に採番。Tシャツ(背中説明図)は G2181(206行目)、カレースプーン(呉鎮守府)は G2017 が既にあった。全商品の JAN と G番号の対応は `data/20261109_items.json`。

## 3. ピッキング用の商品表(SKUDB)に足りない商品を足す

042 の `/api/skudb`(ループバック `127.0.0.1:8303`・PIN不要)。**承認を得てから**:

1. `POST /generate`(item_code・base_name・location、色×サイズがあれば colors[{name,abbr}]・sizes)で行を作る(保存しない)。色は SKUDB の流儀(ブラック=BK・ホワイト=WH)
2. `POST /ops/add` を `commit:false` で照合(errors・warnings が空であること。既にあるSKUは errors で止まる)→ `commit:true`
3. 所在は既存の一覧にある文字列(`12_F2-2階` `01_本店3F` など)。**既存行の所在は勝手に変えない**(11/9 は G2017 が本店3F で、運用者が「そのまま」と決めた)
4. 保存後に SKUDB.csv を読み直して行を確かめる(11/9 は 4309〜4319 行目の 11 行)

## 4. 追加ピッキングの予約

`POST http://127.0.0.1:8303/api/picking-reservations`(記憶 `project_042_026_picking_reservation`)。1商品ずつ:

```json
{"item_code":"G2181","item_name":"…","titles":["カラー","サイズ"],
 "lines":[{"pattern":["ブラック","M"],"qty":5}],
 "memo":"西ロジ 宮島SA 11/17納品 発注書…","requested_by":"…","request_id":"一意の印"}
```

- 色・サイズが無い商品は `titles:[]`・`pattern:[]`。同じ商品の予約は数量が足される。**request_id を付けて再送の二重を防ぐ**
- 直すとき: `GET` で id を見て、`PATCH /{id}` {"qty":n} と `DELETE /{id}`(取消)。11/9 は Tシャツを「黒5×4」に直した
- 予約は、PDFを1枚でも出すと消化される。**ピッキングリストの画面・PDFでは通常のネット注文と区別できない**のが仕様(注記を足さない)
- 積んだ後に合計を発注書と照合する(11/9: 15行・139個)

## 5. 返信メール

`/mail-send` の既定(アーティファクト → DeepSeek 点検 → 承認の画面 → 080 の自動送信)。宛先は中間様。本文の骨子(11/9 版):

- 【秘密事項】(開示範囲:取引関係者に限る)/To:中間様/Cc:(空)
- 発注書(番号2つ)を受け取った/商品は(集める日)に集め、欠品がなければ(発送日)までに発送し、17日の納品に間に合わせる/欠品があれば集めた後すぐに連絡
- Tシャツの色・サイズの復唱/納価入りの納品書と請求書は本社宛て/発送後に発送日入りの発注書をFAXで本社へ
- 「17日納品」を**無条件の約束にしない**(DeepSeek の指摘)

## 6. 発送後に作る2つ(発送前には使わない)

**発送日が確定してから**作る。日付を発送日に合わせる。

### 発送日スタンプ入りの発注書

```bash
python "C:/ClaudeCode/.claude/skills/nishiro-order/stamp_order_pdf.py" \
  --src "\\192.168.1.50\共有スペース\FAX\FAX転送_….pdf" --out "<出力>.pdf" --date 2026-11-12
```

- スタンプは **Eの案**(受付印風・年月日の欄つき・朱)。全ページに、読む向きで水平に押す(画面では文字と同じ90度横向き)。傾けない
- 位置は**読む向きの右下 = 画面の右上隅の摘要欄の右端**。欄の幅が約17mmなので、スタンプは約25×12mm(罫線までの余白は上下に約2.6mm)。色は朱で、FAXで送ると黒く出る。位置を変えるときは `--box X0 Y0 W H`
- **別の発注書で使うときは、位置を目で確かめる**(欄の位置は 2026-11-09 の様式の値)。出力を拡大して(`fitz` の clip で)確認してからFAXする
- 先方の依頼は「納品日」の記入、スタンプは「発送日」。違いを運用者が承知のうえで決めた(11/9)

### 仮納品書(荷物に入れる)

```bash
python "C:/ClaudeCode/.claude/skills/nishiro-order/make_kari_note.py" \
  --items "C:/ClaudeCode/.claude/skills/nishiro-order/data/20261109_items.json" \
  --date 2026-11-17 --out-dir "<出力フォルダ>" --copy
```

- 様式は 900.ClaudeCode/納品書発行 の納品書(紺の帯・金額なし)を流用し、題名を「仮納品書」・列を **JANコード・自番号・商品名・数量・賞味期限** にしたもの。**賞味期限は全商品「対象外」**(賞味期限の対象になる商品が無いとき。あれば JSON の `expiry` に書く)
- 納品先は藤井産業㈱ 宮島SA(上) 一括TOMS 御中。**納品予定日**は納品希望日(11/9 は 2026年11月17日)。発注書が2枚あっても1枚にまとめた
- 新しい発注では、`data/YYYYMMDD_items.json` を JANと G番号の対応から作る(JSON は 1行1商品。内訳があれば `sub`)
- `--copy` は Downloads と NAS(999.一時ファイル)へ写して照合する。印刷は運用者の指示で(標準プリンターへ1部)

## 守ること

- スタンプ入りの発注書と仮納品書は、**実際に発送した後**に使う。発送前に作って送らない
- メールの送信・FAX送信は運用者が行う(メールは承認の画面で運用者が承認)
- 発注書の画像(個人情報ではないが取引先の書類)を外部の AI へ送らない
- 納品日をFAXで返す要否は、先方に確かめていない(11/9 時点)。必要と言われたら、発注書の印字(2026/11/17)を確認して返す
