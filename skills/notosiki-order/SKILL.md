# /notosiki-order — ダンボールワン 再注文（確認画面まで）

ダンボールワン（`https://www.notosiki.co.jp/`、運営ラクスル）で、**過去に買った商品の再注文**を Claude in Chrome で自動操作する。

## ⭐ 2026-10-18〜 端末 A の Playwright スクリプトが正（Chrome 拡張の手順は下に参考として残す）

端末 A の `C:\ClaudeCode\900.ClaudeCode\notosiki_order`（README あり）で実行する。TK など他の端末からは申請 JSON を A へ送る。

- 申請 JSON（**`ship_to` 必須**。無い申請は rejected）:
  `{"source":"TK","ship_to":"セブンエス","items":[{"code":"K-60","lots":1}]}`
  - `ship_to` = お届け先一覧（お客様情報の住所＋お届け先リスト）の表示の一部。**ちょうど 1 件に当たったときだけ**選ぶ（0 件・2 件以上は rejected で候補を返す）。
    2026-10-18 時点の一覧: 株式会社制服のフジ 寺下 貴之（本社・呉市中通）／セブンエス株式会社(制服のフジ担当)（堺市）／
    サスガワークス合同会社 寺下 由利子（岩国市）／革工房リッキー合同会社 長張 力（大阪市大正区）。「合同会社」のような共通語は 2 件に当たる。
- 流れ: カートに残りがあれば**全部削除**（消した行は結果と LINE に載る）→ カートへ → 突き合わせ → ご注文情報設定 → **お届け先を ship_to で選んで読み直し確認**
  → **「お支払い方法を設定する」まで押す** → **ラクスルにログイン**（keyring `a_browser:raksul`。ダンボールワンとは別の ID。登録は `python -m a_browser_common.setup_credentials raksul`。「ログインしたままにする」に印）
  → **お支払い方法の画面で止める**（支払い方法は前回のカードのまま触らない）。**注文の確定は運用者が窓で押す**。
- **2026-10-18〜 実行は LINE の承認が必須**(全実行入口で強制)。Claude は `enqueue` だけ行い、見張り役 `a_browser_watch` が運用者の LINE 承認のあと `run --request-id N --approval CODE` で起動する。承認コードなしの `run` は動かない。詳細は `a_browser_watch/README.md`。
- 追加認証が出たら突破しない（窓を渡して止める）。

- 商品一覧データ（正本）: `C:\ClaudeCode\094.Chrome自動操作\notosiki\purchased_items.json`（79件。取得日はファイル内 `fetched`）
- 一覧アーティファクト（検索・選択・指示文コピー）: `094.Chrome自動操作\notosiki\purchased_items.html` を公開したもの
- 画面の観察記録（2026-10-14）: `094.Chrome自動操作\docs\notosiki_screens.md`

## 🚨 絶対ルール

1. **支払い・注文確定は Claude が行わない。** 「ご注文内容の確認」画面（またはその次の支払い方法入力画面）で止まり、内容を報告する。
2. ID・パスワードは入力しない。ログイン画面は Chrome の自動入力済みなので、**「ダンボールワンアカウントでログイン」ボタンを押すだけ**。入力欄が空ならユーザーに手動ログインを頼む。
3. 指示にない商品・数量・オプションを足さない。ポップアップの前回オプション（広告・色・印刷・枚数）は**変更しない**（変更が必要ならユーザーに確認）。
4. カートに別の商品が既にあれば、先にユーザーに伝える（再注文のカート追加は、既存のカートに足される）。

## 用語（ユーザー定義 2026-10-14）

**1ロット = サイトの「数量 1」= 1販売単位。** 例: K-60 は160枚、A4-H26 は300枚。
JSON の `price_ex_tax` は1ロットあたりの税抜価格、`lot_qty` は1ロットの枚数。`last_quantity`（前回の数量）は参考値で、**指示がなければ使わない**。

指示の形: 「**K-60 を 1ロット**」「**A4-H26 を 2ロット**」。ロット数 = ポップアップの「数量」プルダウンの値。

## 手順

### 0. 準備
- 指示を読み、JSON の `item_no` と照合（無い品番はユーザーに確認）。**G番号ではなくダンボールワンの品番**（K-60 など）。
- Chrome ツールを一括ロード（ToolSearch `select:mcp__claude-in-chrome__tabs_context_mcp,…navigate,computer,find,read_page,get_page_text,javascript_tool,tabs_create_mcp,tabs_close_mcp`）。
- `tabs_context_mcp {createIfEmpty:true}` で作業タブを決める。**前面のタブが別サイトだと、裏のタブは描画が止まり screenshot がタイムアウトする**。使い終わった別サイトのタブは閉じる。

### 1. ログイン
1. `https://www.notosiki.co.jp/mypage/order_history?tab=1` を開く（未ログインなら `/mypage/login` に飛ぶ）。
2. 自動入力を確認し（3 秒待つ）、`find`「ダンボールワンアカウントでログイン」→ ref でクリック。8 秒待つとマイページ（「購入した商品」79件）になる。

### 2. 商品をカートに入れる（1商品ずつ）
1. 「購入した商品」の一覧（1ページ21件。ページ送りは **「購入した商品」側のリンク**。「注文履歴」側と ref が別に出るので注意）から、品番の行の「**ご注文手続きはこちら**」を探す。`find` は注文履歴タブの行も返すので、**「購入した商品」側（ref 番号が大きい方）**を選ぶ。リンク先は `/popup/popup_rm?key=…&via_mypage=1`（再注文ポップアップ）。
2. `scroll_to` → 3 秒待つ → クリック → **8 秒待つ**（反応が遅い。無反応なら screenshot で確認して 1 回だけ押し直す）。
3. ポップアップ（iframe。`find` に出ない）が開く。**座標クリックで操作する**:
   - 前回のオプションが選ばれている（広告・色・印刷・枚数）。変更しない。
   - **数量プルダウン**が既定で「1（○○枚）」。ロット数が 2 以上なら、プルダウンをクリック → **キー ArrowDown × (ロット数−1) → Return**（ネイティブ選択肢は screenshot に写らない）。zoom で「2（600枚）」のように確認する。
   - 赤い「**カートに入れる**」をクリック（ポップアップ内。スクロールが必要な商品は、ポップアップ内でスクロール）。
4. 「商品がカートに追加されました（○点・合計 ○円）」が出る。次の商品があれば「お買い物を続ける」で閉じ、手順 2 を繰り返す。最後の商品は「ご注文手続きへ」。

### 3. カートの確認・数量の修正
- `https://www.notosiki.co.jp/cart` は通常の DOM（`find`/`read_page` が効く）。品番ごとに「数量を減らす」「商品数量」「数量を増やす」「削除」がある。数量を直すときはここで行う。
- 商品ページは `https://www.notosiki.co.jp/item/detail?num=<品番>`。
- `get_page_text` で、商品小計・送料・消費税・合計（税込）を読む。

### 4. ご注文内容の確認（ここで止まる）
- `ご注文手続きへ` → `https://www.notosiki.co.jp/order/order?…`（「ご注文内容の確認」）。
- 読み取って報告する: お届け先（自動設定: 株式会社制服のフジ、呉市中通1-1-21）、各商品（品番・入数・梱包方法・個口数 × 数量・小計）、出荷予定日（「最短で 10/14（水）」。平日 15 時まで当日出荷）、お届け希望日・時間、領収書、商品代金（税抜）・送料・消費税・**合計（税込）**。
- 次のボタン「**お支払い方法の入力へ進む**」は確定ではないが、**ユーザーの指示があるまで押さない**。支払い方法は、クレジット・代引・NP請求書払い・銀行振込・AmazonPay・ラクスル請求書払い。

### 5. 完了後の検証（必須）
- ユーザーが確定したと伝えてきたら、**クエリなしの** `https://www.notosiki.co.jp/mypage/order_history`（注文履歴。先頭が最新）を開き、`get_page_text` で最新の注文を読む（8〜10 秒待つ）。
- 照合項目: 注文番号（7桁）・注文日・状態（手配中）・各商品の品番と数量（`160枚×1` の形）と単価・合計金額（税込）・お届け先・支払い方法。**カートで報告した内容と一致するか**を表で返す。
- 実績: 2026-10-14 の注文 #5816211（K-60 / A4-H26 / S-K80 を各 1 ロット、合計 23,453円・クレジットカード）は、カートと完全に一致した。
- 注文履歴の各注文には「この注文の商品をカートに入れる」（まとめ再注文）がある。同じ内容を繰り返すときに使える（使う前にユーザーに確認）。
- 過去の支払い方法は**すべてクレジットカード**。お届け先の履歴: 制服のフジ（既定）、セブンエス、サスガワークス、革工房リッキー。お届け先を変えたいときは、確認画面の「お届け先 変更」で行う（要ユーザー確認）。

## 待ち時間・注意（サイトが重い）

- ボタンを押したら **最低 3 秒、通常 8〜10 秒待つ**。screenshot がタイムアウトしたら、待って再試行（フリーズではなく描画待ち）。
- URL にクエリ（`?tab=1` など）が付いたページでは、`javascript_tool` の結果が「BLOCKED: Cookie/query string data」になる。`get_page_text` を使うか、クエリなしのページ（ページ送り後の `/mypage/order_history`）で実行する。
- `computer` の `wait` は最大 10 秒。

## JSON の更新

商品が増えたら、「購入した商品」を全ページ読み直して `purchased_items.json` を更新し、アーティファクト（`purchased_items.html`）を再公開する（生成: `template.html` の `__DATA__` を JSON で置換）。
