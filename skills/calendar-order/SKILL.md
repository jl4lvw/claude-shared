# calendar-order — カレンダーの発注と実績表

作業フォルダ: `C:\ClaudeCode\.claude\skills\calendar-order`。2026-10-22 に寺下さんの指示で作成。

## 0. 発注の前に必ずやること(省略禁止)

```bash
PYTHONIOENCODING=utf-8 python C:/ClaudeCode/.claude/skills/calendar-order/calendar_status.py
```

品目ごとに「**昨年の販売数**」「**今年の発注累計**」「**今年の入荷**」「昨年との差」が出る。この表を、発注の数量を相談する前に本文へ貼る(質問ボックスだけで終えない)。

- **昨年の販売数 = 昨年の仕入数**。昨年は仕入れた分をすべて売り切った(2026-10-22 寺下さん確認)。コンパスの仕入記録(conphas-search・読み取り専用)から、シーズン(9/1〜翌8/31)ごとに自動集計する
- 今年の発注は `orders.json`(発注台帳)に残す。コンパスの仕入は入荷してから計上されるので、発注済み・未入荷は台帳側にしか出ない
- コンパスの仕入計上は実際の到着日とずれることがある。表の「今年の入荷」は目安

## 1. 仕入先ごとの発注の仕方

- 2027年版の案内は、2026-10-22 時点で見つかっていない(取り扱いの確認から)

## 2. 手順

1. 実績表を出す(上記)
2. 仕入先・品目・数量を決める(昨年の販売数に対して今年がいくつかを見ながら)。数量は寺下さんが決める。勝手に決めない。**寺下さんは実績表の左の「番号」と「○個」または「○ロット」で指示する**(1ロット=実績表の「1ロット」の部数。例: 「2を3ロット」=BOOK A4を150部、「1を40個」=将A2を40部)。番号は `ITEMS` の並び順で、品目を足したときは末尾に足して番号をずらさない
3. **注文書PDFとメール本文を作る**(三将。2026-10-22 の追加注文で確定した形)
   - 注文書PDF: `C:\ClaudeCode\017.Tシャツなどの注文\make_photo_order_form.py`(`PhotoOrderForm`/`PhotoItem`)で、前回と同じ体裁(品名・JAN・入り数(ケース数)・部数・納品先・備考)。商品画像は `017.Tシャツなどの注文\三将\images\c1〜c4.jpg`(番号1〜4の順)。出力は `017.Tシャツなどの注文\orders\<日付>_注文書_三将_2027年カレンダー.pdf`。備考は「2027年版カレンダー」(「追加」とは書かない・寺下さん指示)。作り方の実例: `C:/tmp-ai/sansho_add_order.py`
   - メール本文: 10/16と同じ書式(冒頭3行・「いつもお世話になっております。寺下＠制服のフジです。」・▼品名：JAN／部数（ケース数）・合計・納品先・注文書添付・署名)。「2027年版カレンダーについて、下記のとおり注文いたします。」の1文。**「追加」「別」とは書かない。サンプルの依頼は初回のみ。納期は指定しない**(三将の案内は入荷10月上旬)。件名は「2027年版カレンダーの注文（4品目・計○部）」
   - 署名は mail-send の標準(「  -=-=-=-=-」は先頭に空白2つ、最後は「━－━－━－━－━」)。過去のメール履歴の署名は崩れていることがあるので写さない
4. **送信前チェックと承認(2026-10-22 確定・LINE WORKS の承認で自動送信)**
   - 4段階チェック(tshirt-order スキルの「メール送信前チェック」): ①テンプレ全文 ②前回のメールとの比較 ③DeepSeek レビュー(`.claude/tools/deepseek_coder.py --role reviewer`。既定事項リストを添える。採否はClaudeが判断) ④納期10日ゲート(納期指定が無いときは対象外)。チェックした時刻(JST)を控える
   - アーティファクトで、送信予定のメール(差出人・宛先・件名・添付・本文・注文書の画像)を見せる。寺下さんが「LINE WORKS の承認で送る」と決めたときは、アーティファクトで止まらず次へ進んでよい(承認の本体は下の見張り役の承認)
   - 依頼zipを作って 080 へ提出する(`purpose` は6〜120字・人名・住所・電話・アドレスは書かない):
     ```bash
     python C:/ClaudeCode/.claude/skills/calendar-order/send_via_080.py submit --to sanshoasaka@kksansho.co.jp --subject "件名" --body-file 本文.txt --attach 注文書.pdf --purpose "2027年版カレンダーの仕入先への注文(420部)" --work-dir C:/tmp-ai/sansho_job --four-stage-at <ISO JST> --deepseek-at <ISO JST> [--dry-run]
     python C:/ClaudeCode/.claude/skills/calendar-order/send_via_080.py wait <job_id> --minutes 40   # 裏で待つ
     ```
   - **承認は寺下さん本人だけが行う。Claude は承認しない。** 承認は見張り役が LINE WORKS と承認の画面(approve.sfuji.f5.si)に出す。**添付のあるメールは承認の画面で添付の画像を確かめたときだけ承認できる**(LINE WORKS のボタン・文の返信・電話では中止だけ)。寺下さんには「承認の画面で承認してください」と案内する
   - 提出後は止まらず、`wait` を裏で待ち、結果(送信済み・写しの照合)を読んでから報告する。送信済みフォルダの写しが承認した内容と一致するかも確かめる
   - 承認の放置・却下・失敗のときは、状況をそのまま報告する(勝手に再提出しない)
5. **送信を確認したら、発注台帳に記録する**(忘れると次回の実績表が狂う):
   ```bash
   python C:/ClaudeCode/.claude/skills/calendar-order/calendar_status.py add-order --supplier 三将 --item "将カレンダー A2 海上自衛隊 縦型" --qty 30 --date 2026-10-16 --note "注文書メール"
   ```
   `--item` は表示名のほか番号(実績表の左の数字)でもよい。ロット数で指示されたら `--qty 部数` の代わりに `--lots ロット数` を使う(1ロットが未設定の品目は `--qty`)。一覧は `python calendar_status.py items`
6. 入荷したら、コンパスの仕入計上が済んでいるかを実績表で確かめる

## 3. 品目を足すとき

`calendar_status.py` の `ITEMS`(表示名・仕入先・品名のキーワード)に1行足す。コンパスの品名は半角カナなので、NFKC正規化した全角で書く。足したら実績表を実行して、昨年の数が出るか確かめる。

## 4. 守ること
- コンパスは読み取りだけ。書き込みはしない
- 金額は税込で見せる(下代・仕入も)
- 昨年の販売数は「仕入=販売」の前提。売れ残りが出た年は、この前提を見直す(寺下さんに確認)
- このスキルの置き場は `.claude/skills/calendar-order/` の1か所だけ
