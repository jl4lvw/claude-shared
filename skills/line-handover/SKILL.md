# /line-handover — 090 で止まった受付を Claude のセッションで引き継ぐ

2026-11-01 運用者決定: **090 ができないことは「できません」と返信して終わらせない。** 要対応(needs_fix)にして LINE WORKS で運用者に知らせ、
Claude のセッションがこの手順で引き継ぐ。決まりで断ってよいのは E(送金・振込・削除・自身の設定変更・テスト送信・権限/認証の変更)だけ。

道具: `C:\ClaudeCode\090.LINE業務指示エージェント\scripts\claude_handover.py`(中身は `api/handover.py`。状態の変更は `line_tasks.operator_set_status` を通すので監査に残り、LINE WORKS に知らせが出る)。

## 090 は引き継ぐ前に、要る情報を承認の画面で聞いてそろえる(2026-11-01 運用者決定)

すぐ引き継ぐのではなく、**実行に要る情報を運用者とラリーして、「実行するところ」まで来てから** Claude に渡す。

1. 判断 AI が「090 では実行できない」(unsupported、または決まりの語の無い blocked)と返すと、090 は依頼の形(メルマガ / 無地Tシャツ / Tシャツの注文 / LINE / 在庫)を見て、
   引き継ぎに要る項目を **承認の画面の質問【引き継ぎの確認】** として 1 回出す(自由記述。依頼文に書いてあるものは「依頼のとおり」でよい)。LINE WORKS には「確認があります」と届く
2. 運用者が回答すると調べ直しに戻り、AI がまた「実行できない」と返した時点で、**引き継ぎ票**を理由にして要対応になる。票の中身: 1 行目「Claude のセッションで対応: <依頼の要旨>」・■ 依頼・■ 引用・■ 引き継ぎの確認への回答・■ 090 が止まった理由・■ 対応の手順
3. 合う形が無い依頼(聞く項目が決まっていないもの)は、聞かずに票を付けて要対応にする

**回答が無いままの受付は要対応にならない**(回答待ち `waiting_input` のまま。7 日で自動破棄)。一覧(手順 1)に出ていないのに「止まっている」と言われたら、承認の画面の回答待ちを見る。
聞く項目は `api/handover.py` の `_KINDS`。依頼の形を足すときはここに項目を書き、`docs/capabilities.md` の表も直す。

## 手順

### 1. 一覧を読む
```
cd C:\ClaudeCode\090.LINE業務指示エージェント
python scripts/claude_handover.py list
```
要対応(090 が止めた)と対応中(Claude が引き取った)を古い順に出す。表の「使う手順」は止まった理由の案内(`stops.guide`)から拾ったスキル名。
`--all` で対応済みも出す。`--json` で機械向け。**表は会話に貼ってから**次に進む(運用者がどれを頼んでいるか確かめる)。

### 2. 1 件の中身を読む
```
python scripts/claude_handover.py show <受付番号>
```
依頼の全文・引用・止まった理由(= 引き継ぎ票。「■ 引き継ぎの確認への回答」に運用者が承認の画面で答えた配信日時・送り先・枚数などが入っている)・使う手順。引用だけの依頼(「対応して」+引用)は引用が本文。
**票にある回答をそのまま使って実行する**(同じことを運用者に聞き直さない。足りない項目だけ聞く)。

### 3. 引き取る
```
python scripts/claude_handover.py take <受付番号> --note "<何をするか 1 行>"
```
受付が手動対応待ち(manual)になり、理由の頭に【Claude のセッションで対応中】が付く(運用者が承認の画面で「調べ直す」を押さないように)。LINE WORKS の運用者 1 対 1 に知らせが出る。

### 4. 案内された手順で対応する
止まった理由の「■ 対応の手順」に出たスキルを呼ぶ(スキル連鎖はしない。Claude が次のターンで呼ぶ):

| 依頼 | 手順 |
|---|---|
| LINE の配信予約(メルマガと混在・両店同時・下書きが無い・ログイン切れ で 090 が止めた) | `/rakuten-line-reserve` / `/yahoo-line-reserve` |
| 楽天メルマガの手配 | `/rakuten-merumaga-flow`(下書きまで)→ 運用者の「送信手続き」で `/rakuten-merumaga-reserve` |
| 無地Tシャツの手配(ステッチハウス) | `/stitchhouse-tee` → `/toms-web` |
| Tシャツ・ポロ・パーカーの注文の実行(090 は確認まで) | `/tshirt-order` |
| バリエーション(色・サイズ)の追加 | `/mall-product-update` |
| 在庫変更で 092 に無い SKU・読めない SKU | 092(自社の在庫管理)の画面で SKU を台帳に載せてから、承認の画面で「補足して調べ直す」(090 の set_stock で続く) |
| 案内が無いもの | 依頼の内容から手順を選ぶ。無ければ運用者に相談(勝手に断らない) |

承認が要る操作はすべて承認の画面(PWA)で。LINE グループへの報告は `/line-notify`(承認の画面で承認を受けてから)。

### 5. 対応済みを記録する
```
python scripts/claude_handover.py done <受付番号> --note "<何をしたか: 承認コード・配信日時・ID・確認した観点・気づいた点>"
```
理由が【Claude のセッションで対応済み】+ note になる(受付 #51 の型)。一覧から消える(`--all` で見える)。
**途中で止める・できないと分かったときも done にせず、`take` の note を直すか、運用者に相談する**(「できません」で閉じない)。

## 決まり
- 承認はすべて承認の画面。チャットで承認を求めない
- LINE グループへ承認なしに投稿しない
- 受付の状態は道具(= `operator_set_status`)でだけ変える。DB を直接 UPDATE しない
- 運用者が破棄(rejected)した受付は、確かめずに戻さない(090 の CLAUDE.md)
- 090 の `api/` を変える作業ではない。ここは引き継ぎの運用手順
