# fin — アーカイブ前の締め（振り返り・スキル見直し・メモリ見直し）

アーカイブの前に毎回お願いされている3つの見直しを、1回の呼び出しで行う。
**書き込みは提案の表を運用者が承認した行だけ。** アーカイブ自体は運用者の操作に残す（Claude は行わない）。

## 守ること（先に読む）

- **事実の裏づけがない改善はしない。** 提案には必ず「今回のセッションで実際に起きたこと」を1行添える（訂正された・詰まった・手順が古かった・うまくいった型）
- **スキルの編集は project の `.claude/skills/<name>/` だけ。** ユーザー階層（`~/.claude/skills`）へ書かない（同名があるとそちらが優先され、直しが隠れる）
- **メモリは新規追加より既存の更新を優先する。** 重複を作らない。コード・git履歴・CLAUDE.md で分かること、このセッションだけの話、秘密の値（PIN・パスワード・API キー）は書かない
- **スキル連鎖はしない。** `/g-ul` などは自動で呼ばず、最後に「実行しますか」と出す
- **会話に書く言葉はすべて日本語。** 表は本文に貼ってから聞く（質問ボックスだけで終えない）
- 深さは自動で決める（短いセッションは短く・長いセッションは材料集めを厚く）。選択肢で聞かない
- 記録には人名・お客様名・住所・秘密の値を書かない

## 手順

### 1. 材料集め（読み取りだけ・サブエージェントに委譲）

長い会話の試行錯誤を本会話に積まないため、材料集めは `Agent`（general-purpose）に任せ、**要約だけ**を受け取る。
依頼文に入れること（毎回この形）:

1. 文脈台帳を見る: system prompt の scratchpad ディレクトリ名が `<SID>` → `python C:/ClaudeCode/.claude/hooks/ctx_cli.py show <SID>`（glob で別セッションの台帳を探さない）
2. このセッションで**実際に使ったスキル**の `SKILL.md` を読む（`python C:/ClaudeCode/.claude/tools/skill_scope.py where <name>` で実効パスを確かめてから）
3. 関連メモリを読む: `C:\Users\user\.claude\projects\C--ClaudeCode\memory\MEMORY.md` の索引と、該当するハブ・個別メモリ
4. 次の観点で、このセッションの出来事を**事実だけ**抜き出して返す（推測・評価は書かない）:
   - ユーザーに訂正された・差し戻された・指摘された箇所と、その内容
   - 手順どおりでは進まず、別の方法に変えた箇所（DB に無かった・書式が違った・道具が止まった等）
   - 一度で通った箇所（次回もそのまま使える型）
   - 終わっていないもの（キュー・待ち・未実施の手順）
5. サブエージェントには、ファイルを書き換えないこと・並列起動しないことを明記する

返ってきた要約を**そのまま信じず**、提案に使う箇所は自分で一次資料（SKILL.md の該当節・メモリの本文）を開いて確かめる。

### 2. 提案の表を作る（3観点・1つの表）

本文に表を貼る。1行=1提案。列は固定:

| # | 観点 | 対象（ファイル・節） | 提案（何をどう変える） | 根拠（今回起きたこと） | 適用 |
|---|---|---|---|---|---|

観点ごとの基準:

- **振り返り（R）**: うまくいった／詰まった／直された／次回に効く教訓／残件。**表の外に短い文章でも書く**（3〜6行）。メモリに昇格するのは教訓だけ
- **スキル見直し（S）**: 今回使ったスキルの手順と実際の食い違い。直す節・直し方を差分の形で示す（例「Step 0.5 に ○○ を足す」）。**今回の事実で裏づけられないもの・好みの変更は出さない**
- **メモリ見直し（M）**: 次のいずれか
  - 追加（feedback＝運用者の指示や訂正、project＝進行中の事情、reference＝外部の置き場所、user＝運用者について）
  - 既存の更新（古くなった記述・食い違いの修正）
  - 削除（誤り・重複・もう当てはまらないもの）
  - `MEMORY.md` の索引の整合（1メモリ1行・リンク切れ・重複行）

提案が無い観点は「提案なし」と理由を1行書く（黙って飛ばさない）。

### 3. 一括承認

表を本文に貼ったうえで、**1回だけ**承認を取る（`AskUserQuestion`・ボタン）:
「すべて適用／行を指定して適用（Other に番号）／適用しない」。
書き込み・削除・本番への反映を伴う提案は、承認された行だけ実行する。承認の無い行には触れない。

### 4. 適用と検証

- 既存ファイルを書き換える前に `.bak_YYYYMMDD_HHMMSS` を残す（メモリの追加・削除は除く）
- スキルを直したら**実効コピーで確かめる**: `python C:/ClaudeCode/.claude/tools/skill_scope.py where <name>` の実効パスが編集した場所と一致し、`python C:/ClaudeCode/.claude/tools/skill_scope.py check` が exit 0
- メモリを直したら: 新規ファイルのフロントマター（name / description / metadata.type）と `MEMORY.md` への1行追記、`[[リンク]]` の先が存在することを確かめる
- 文字コードは UTF-8。Python で書き戻すときは `newline=""`（CRLF 化を防ぐ）
- 検証の結果を表（# ごとに OK／NG）で本文に出す。NG は直すか、理由を添えて報告する

### 5. 振り返りの記録

`C:\ClaudeCode\.handoff\retro\YYYYMMDD_<セッション名>.md` に1ファイル残す（フォルダが無ければ作る。名前の空白は `_`）。内容:

```
# 振り返り <セッション名>（YYYY-MM-DD）
## やったこと（3〜5行）
## うまくいったこと
## 詰まったこと・直されたこと
## 次回への教訓（メモリへ昇格したものに ★）
## 適用した見直し（スキル・メモリの # と対象）
## 残件
```

人名・お客様名・秘密の値は書かない。ここに書いた教訓のうち、次回の判断を変えるものだけをメモリへ昇格させる。

### 6. アーカイブしてよいかの点検

次を確認し、**残っているものだけ**列挙する（全部OKなら「アーカイブできます」と1行）:

- 未コミットの変更（自分の作業分。他セッションの変更は触れない）
- `/g-ul` が必要な変更（`.claude` 配下を直した場合）→ 「実行しますか」と出す（自動で呼ばない）
- 起動中のプロセス・裏で待っているシェル・一時ファイル（文脈台帳の `STATE` が解除されているか）
- 台帳の `OK`（承認）の実行済み・取り消しの確認
- キュー・予約・翌朝に回した作業（件数と実行予定の時刻）
- 運用者の操作待ちのもの（承認の画面・印刷の確認など）

最後に1〜3行で締める（やったこと・残っていること・次にやること）。
運用者の操作が要る残りがあれば最終行に `【対応待ち】`。なければ付けない。

## やってはいけないこと

- 提案を承認なしで適用する（表を見せる前に書き込む・承認されていない行を適用する）
- 根拠の無いスキル改善・メモリの水増し（「念のため」の追記）
- メモリに、コード・git・CLAUDE.md・スキルに既にある内容を写す
- `~/.claude/skills` や他セッションの台帳・他の作業のファイルへ書く
- アーカイブ・削除（`archive_session` など）を Claude が実行する
