# /rakuten-merumaga — メルマガエディタから貼り付け用タグを取得して保存

楽天市場「制服のフジ」のメルマガ作業の第 1 段。**ここまでで止まる**（2026-10-17 ユーザー指示。以降の工程は未実装）。

```
ログイン → テンプレート一覧 → 更新が 5 日以内の候補をユーザーに選ばせる
→ 編集 → 次へ → 「貼付用タグをコピー」→ 「タグをコピーする」→ ローカルに保存
```

- 対象: `https://mcm.mqm.co.jp/login`（メルマガエディタ for 楽天市場）
- ブラウザ: **Claude in Chrome**（deferred なら ToolSearch で `select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__find,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__javascript_tool,mcp__claude-in-chrome__browser_batch,mcp__claude-in-chrome__tabs_create_mcp,mcp__claude-in-chrome__tabs_close_mcp` を一括ロード）

## 🚨 絶対ルール

1. **配信・送信・テンプレートの保存／コピー／削除／復元はしない。** 触るのは「編集」を開いて「貼付用タグをコピー」を押すところまで。テンプレート名・本文は変更しない。
2. **ID / パスワードは入力しない。** ブラウザの自動入力に任せ、「次へ進む」「ログイン」ボタンを押すだけ。入力欄が空ならユーザーに手動ログインを頼む。
3. **質問は最初にまとめて聞く**（toms-web と同じ）。このスキルで聞くのは「どのテンプレートか」だけ（候補はログイン後にしか分からない）。回答後は止まらずに最後まで進める。
4. 取得したタグの内容は変更しない（改行を LF に揃えるだけ）。
5. **メルマガ（テンプレート）の修正はしない。指摘をするだけで終了する**（2026-10-17 ユーザー指示）。メルマガの修正は別の担当者の仕事で、ここで直すと、次に担当者が作るときに同じミスを繰り返すため。手順 6 の警告・エラーは、内容（どのリンクが・なぜ）を担当者に伝わる形で報告して終わる。
6. **エディタを開くとテンプレートの「更新日時」が変わる**（2026-10-17 実機。10/16 のテンプレートを編集画面まで開いただけで 19:44 → 19:50 になった）。内容は変えていないが、「更新が 5 日以内」の候補判定に影響する。**タグの取得が要るときだけ編集を開く**。中身を読むだけなら、一覧の「プレビュー」（`/upload/file/Temp/<日付>/<id>.html` が認証なしで取れる）を使う。

## 手順

### 1. ログイン
1. `tabs_context_mcp {createIfEmpty:true}` → 空のタブで `https://mcm.mqm.co.jp/login` を開く（描画に数秒）。
2. 画面「サービスの統合により…下の『ログイン』ボタン」の **ログイン** を押す → `auth.mqm.co.jp`（ID/メール）。
3. ID が自動入力済みなら **「次へ進む」** → パスワード画面（自動入力済み）→ **「ログイン」**。
4. 「产品和服务」（中国語のポータル）が出る。**「メルマガエディタ」のカードの「进入系统」**を押す。**新しいタブ**で `https://mcm.mqm.co.jp/`（テンプレート一覧）が開く。
   - ⚠ ポータルのタブを `tabs_close_mcp` で閉じると、新しく開いたタブごとタブグループが消える。**閉じずに、新しいタブ ID を `tabs_context_mcp` で取り直す**か、閉じたあとに `tabs_context_mcp {createIfEmpty:true}` → `https://mcm.mqm.co.jp/` を開き直す（ログイン状態は残る）。
   - タブ ID が「同じグループに無い」と言われたら、`tabs_context_mcp {createIfEmpty:true}` で取り直す。

### 2. 候補の取得（更新 5 日以内）
1. `https://mcm.mqm.co.jp/jp/mail/list`（左メニュー「テンプレート一覧」）を開く。上は見本ギャラリーで、**自分のテンプレートの表は下**にある。
2. 表の列: `（チェック）/ テンプレート名 / SearchKeyword / 作成日時 / 更新日時 / 操作`。**並びは作成日時の新しい順で、更新日時順ではない**（例: 7/10 のテンプレートが 8/10 に更新されている）。**全行の更新日時を見て**、今日から **5 日以内**（今日を含め 5 日前の同時刻以降）のものだけを候補にする。
   ```js
   // javascript_tool(URL にクエリが無いページで使える)
   var t=document.querySelectorAll('table')[0];
   [...t.querySelectorAll('tbody tr')].map(r=>{var c=[...r.querySelectorAll('td')].map(x=>x.innerText.trim().replace(/\s+/g,' ')); return c[1]+' | '+c[3]+' | '+c[4]})
   ```
   - 先頭に `undefined` の行が出ることがある（ヘッダー行）。無視する。
3. 候補が **0 件**なら、「5 日以内に更新されたテンプレートはありません」と報告して**終了**（期間を勝手に広げない）。
4. 1 件以上なら **AskUserQuestion** で、名前と更新日時を並べて選ばせる（1 件でも確認する）。

### 3. 編集を開いて、タグを取得
1. 選ばれた行の **「編集」**（`find` で行を指定して ref クリック。`scroll_to` してから押す）。→ `…/jp/mail/edit/<id>/`（テンプレート名の画面）。
2. **「次へ」**（名前は変えない）→ エディタ（`…/jp/mail/design/?…`）。読み込みに数秒。
3. 上部ツールバーの **「貼付用タグをコピー」**（右から 4 番目あたり。座標クリックが確実。ref クリックが効かないことがある）→ ダイアログが開く:
   - 「元タグ」（上）／「貼り付け用タグ (文字数: N)」（中）／「テキスト抽出」（下）。
   - **必要なのは中段の「貼り付け用タグ」**。その下の緑の **「タグをコピーする」**を押す（「ダウンロード」ではない）。**画面の「文字数: N」を控える**（N は Shift_JIS のバイト数）。
4. すぐに、クリップボードの内容をテキストに保存:
   ```
   python ".claude/skills/rakuten-merumaga/scripts/save_clipboard_tag.py" --expect <N>
   ```
   - 保存先は `C:\ClaudeCode\900.ClaudeCode\000.tmp\merumaga_tag_YYYYMMDD_HHMM.txt`（UTF-8・LF）。
   - 取得したタグが HTML の table でない、または文字数が画面と合わないときは、保存せずエラーにする。もう一度「タグをコピーする」を押してからやり直す。
   - 「クリップボード操作に失敗」→ RustDesk の接続が原因のことがある（memory「Excelクリップボードエラーの原因はRustDesk」）。閉じてもらってから再実行。
5. ダイアログの × で閉じ、`https://mcm.mqm.co.jp/jp/mail/list` へ戻る（保存の確認ダイアログは出ない。何も変更していないため）。

### 4. 報告
- 選んだテンプレート名・更新日時、保存したファイルの**フルパス**、文字数（画面と一致）、先頭と末尾の数行を伝える。
- **ファイルのフルパスは必ず表示**する。このタグを Downloads に置く指示があったときだけコピーする。

### 5. 携帯メルマガ用テキストへの変換（2026-10-17 追加）
昔の携帯電話（テキストしか受信できない端末）向けに、**同じ内容のテキスト原稿**を作る。制約: **全体 5,000 文字以内**・**1 行 100 文字以内**（**ただし URL の行は例外で、長さ無制限**。2026-10-17 ユーザー決定。URL の文字は全体の 5,000 文字には数える）。
```
python ".claude/skills/rakuten-merumaga/scripts/html_to_mobile_text.py" "<手順 3 で保存したタグ.txt>" --out "C:\Users\jl4lv\Downloads\merumaga_mobile_YYYYMMDD.txt"
```
- 変換: 先頭のバナー画像のリンク（文字の無い URL）は外す（`--keep-leading-url` で残せる。2026-10-17 指示）／見出し・段落・表の行・`<br>` で改行／装飾（font・b・img）は捨てる／リンクは「リンクの文字」の次の行に URL（画像だけのリンクは URL のみ）／連続した同じ行は 1 つ／同じ URL が近くに 2 回あれば後の方だけ／商品名・価格・URL は 1 かたまりにして、かたまりの間は空行 1 つ／`<hr>` は短い区切り線。
- 100 文字を超える行は、`。、！？▼` や空白で折り返す。**URL は切らない**（URL の行は 100 文字を超えてよい）。
- **終了コード**: 0=OK／2=5,000 文字超過（**保存しない**。勝手に削らず、削る候補をユーザーに聞く）／3=保存したが、URL 以外で 100 文字超の行あり（折り返せなかった行。画面に出す）。
- 文字数は、改行を 2 文字（CRLF）と数えた値でも上限内かを表示する（安全側）。Shift_JIS に無い文字（絵文字など）があれば警告する。
- **テキスト成果物は Downloads と NAS（`\\192.168.1.50\共有スペース\寺下\999.一時ファイル\`）の両方に置く**（ユーザーのルール）。
- **この制約の出どころ**: 1 行 100 文字は社内ルール。全体の上限は **5,000 文字**で、これは **RMS の入力画面の注記（「docomo・au・SoftBank とも全角 5,000 文字」）と一致する公式の制限**（端末 A の観察、2026-10-17）。一時的に 8,000 文字へ変えたが、RMS の制限と合わないため、**同日に 5,000 文字へ戻した**（ユーザー決定）。公開情報の調査では、楽天のモバイルテキストの文字数の数字は見つからなかった。確認できたのは次のみ:
  - 携帯（キャリアアドレス宛）へは「モバイルテキストメール」か「モバイルHTMLメール」を選ぶ必要がある（PC テキスト・HTML・レスポンシブは届かない）。月の配信可能数に上限がある。装飾・画像は不可。
  - 楽天トラベルの携帯向けガイドが本文を約 250 文字としているが、旅館向けの推奨で、上限ではない。
  - メールの規格（RFC 5322）は、1 行 998 文字まで（必須）・78 文字以下が望ましい。ドコモ等は 1 行 1,000 バイト超だと受信拒否。URL の行を長くしてよい（133 文字など）のは、この範囲内なので問題ない。
  - 正確な上限は、RMS の「メルマガ配信」→「メール本文編集」でモバイルテキストを選んだ画面の表示（残り文字数・エラー）で確かめるのが確実。
- 旧版（NAS `メルマガテキスト作成.zip` の `ev_メルマガテキスト作成`）は、正規表現の置換だった。これを HTML を正しく読む方式に作り直した（装飾タグの入れ子・改行・リンクの扱いが安定）。

### 6. 内容のチェック（リンク切れ・説明違い・欠品）（2026-10-17 追加）
```
python ".claude/skills/rakuten-merumaga/scripts/check_mail_links.py" "<手順 3 のタグ.txt>" [--json 結果.json]
```
商品は **RMS API**（商品 API の bulk-get ＋ 在庫 API 2.1 の bulk-get。ページを開かないので速い）、商品以外のリンクは HTTP で確認する。**読み取りだけ**（書き換えない）。認証情報は `040.RakutenOkaimonoMarathon\.env`（値は表示しない。`RMS_API_DIR` で場所を変更可）。

| 確認 | 方法 | 結果 |
|---|---|---|
| ① リンク切れ | 商品: RMS に商品が無い／「非表示」／商品以外: HTTP 4xx・ページ名が「エラー」・別サイトへ移動／検索結果が 0 件 | 警告 |
| ② 説明との食い違い | メルマガの商品名と RMS の商品名の一致度（60% 未満は要確認、30% 未満は「違う商品の疑い」）／メルマガの価格が RMS の表示中バリエーションの価格に無い／カテゴリ等のリンク名とページ名 | 警告 |
| ③ 欠品 | RMS 在庫: 表示中バリエーションの在庫合計。1 つでも 0 のバリエーション → 「一部欠品」／商品全体が 0 → 「欠品」 | 警告 |
| ③' **全商品が販売不可** | メルマガの商品すべてが在庫 0 または非表示 | **エラー（終了コード 2）** |

- 終了コード: 0=問題なし／1=警告あり／2=エラー（全商品が販売できない）。**一部の欠品は警告**、全部が欠品のときだけエラー（ユーザー指示）。
- クーポンのリンクは、ページへの到達だけ確認する（内容・期限はログインが要るため未検証と表示）。
- 汎用の案内文（「▼▼ 特設会場はこちら ▼▼」など）は、ページ名と照合しない。楽天の中のドメイン移動（rakuten.ne.jp → rakuten.co.jp）は問題にしない。
- 実機での最初の確認（10/16 のテンプレート）: リンク 38 本・商品 20 点。警告 5 件 = 一部欠品 1（G1510-L）／検索リンク 3 件（20倍・10倍・5倍）が **実際に 0 件**（ブラウザで確認。商品名に「20倍」を含む商品が今は無い）／「アウトドア」のカテゴリが **404**（リンク切れ）。
- 警告は、送る前に人が見て判断する（直す／そのまま送る）。このスクリプトは直さない。
