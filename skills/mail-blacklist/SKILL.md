# mail-blacklist — 除外(ブラックリスト)の提案と反映

作業フォルダ: `C:\ClaudeCode\900.ClaudeCode\mail-search\scripts`

MC でチェックしたメールのうち、毎回候補に出てくる広告・自動配信を、**差出人・件名・内容を見て個別に判定**して
除外ルール(`exclude_rules.json`)へ足す。**提案までは自動、反映は運用者の承認後だけ。**

## 手順

1. **提案を出す(何も書かない)**
   ```bash
   python C:\ClaudeCode\900.ClaudeCode\mail-search\scripts\blacklist_propose.py propose
   ```
   台帳番号を絞るなら `--nos 208 214`。提案は `out/blacklist_proposals.json` にも残る。
2. **提案をアーティファクトまたは本文の表で運用者に見せる**(提案番号 P1…・判定・差出人・件名・根拠・規則案・過去に当てた影響)。
   `提案` と `要確認` を分けて見せ、`提案しない` は理由だけ短く添える。
3. **運用者が承認した提案番号だけ**を反映する(承認が出るまで実行しない)。
   ```bash
   python C:\ClaudeCode\900.ClaudeCode\mail-search\scripts\blacklist_propose.py apply P1 P2 P3
   ```
   反映は「除外ルール追加(`.bak_日時` を残す)→ ルールの妥当性検査 → 該当の台帳を不要にする」。
4. 反映後に `python triage.py --days 3 --show-excluded` で、落ちたものが想定どおりか確かめて報告する。

## 判定の方針(ツールに入っている)

| 判定 | 条件 |
|---|---|
| 提案しない | 保護リスト(官公庁・学校等)/ フォーム経由 / 社内ドメイン / 当方から返信した履歴あり / 依頼らしい語がある |
| 提案 | 自動配信らしい差出人や広告の件名で、過去に何通も届いて一度も返信していない |
| 要確認 | 返信ゼロで届き続けているが、広告と言い切れない(例: 公的機関の配信、通知メール) |

- **共有サービス(Amazon・メルカリ・Yahoo!・楽天等)は差出人だけで切らない。** 件名との AND にする。
  件名の型から安全に切れないもの(Amazon の注文キャンセル等)は提案しない
- 規則案ごとに、過去の全受信へ当てた結果(当たる通数・保護で救われる通数・依頼らしい通数)を出す。
  **依頼らしい通数が 1 以上なら `提案` ではなく `要確認` に下げる**
- 迷ったら残す側。除外は業務判断なので、`要確認` は必ず運用者に聞く

## 守ること

- 反映前に除外ルールを書かない(提案の段階で `exclude_rules.json` は変わらない)
- 反映できるのは、提案ファイルに規則案がある提案だけ(`提案しない` は反映できない)
- `exclude_rules.json` を手で整形し直さない(`apply` が UTF-8・LF を保って書く)
- テスト: `python -m pytest C:\ClaudeCode\900.ClaudeCode\mail-search\tests\test_blacklist_propose.py -q`
- 置き場はこの 1 か所だけ。他の PC へは `/g-ul` → `/g-dl`
