# delivery-note — 金額なしの納品書

作業フォルダ: `C:\ClaudeCode\900.ClaudeCode\納品書発行`(書式は `template.html`、作成は `make_delivery_note.py`)。
2026-10-27 に注文 20-10034600(森川商店・8品目97点)で作って印刷した書式が元。

## 0. 先に確かめること

- **pickorder の案件(大和ミュージアム・丹青社・神戸海洋博物館・潜水艦桟橋セブンイレブン)なら、このスキルではなく pickorder で出す。** 金額入りの納品書が要る相手もこのスキルの対象外
- 森川商店は委託販売。出荷は在庫の移動なので、**売上の登録・請求書は作らない**(請求は月末の販売報告から。記憶 `project_morikawa_shoten_consignment`)
- 同梱で送る注文が他にないか、受注データ(042)で同じ届け先の未出荷の注文を見る。あれば受注番号を並べて1枚にまとめる

## 1. 見本を作る(印刷しない)

```bash
cd "C:/ClaudeCode/900.ClaudeCode/納品書発行"
python make_delivery_note.py <受注番号> [<同梱の受注番号> ...] --recipient "森川商店 防衛省市ヶ谷店"
```

- 森川商店は受注データの会社名に空白が無いので、`--recipient "森川商店 防衛省市ヶ谷店"` を付ける
- 納品日は今日。別の日にするときだけ `--date YYYY-MM-DD`
- **在庫が足りない商品があるとき**は `--sent 品番=納品数 ...`(例 `--sent G2055=0 G1519=5`)を付ける。数量は納品数になり、備考に「不足あり」、下にオレンジの「不足のご連絡」の欄が出る。納品0の品も数量0の行で残す(11/7 運用者決定)。発行前に数が揃っているかを運用者へ確かめる
- 不足分をどうするか(後日送る・取り消す・送料など)は運用者に聞き、`--shortage-note "文"` で不足のご連絡の欄に入れる。推測で書かない
- 受注データに無い注文はエラーで止まる。推測で作らない(GoQ の取込を待つか、運用者に聞く)
- できた PNG を Read で見て、2ページ目に溢れていないか・品名が切れていないかを確かめる

## 2. アーティファクトで見本を見せて承認を得る

- `out/納品書_…html` の内容をアーティファクトで出す(先頭に「見本です(まだ印刷していません)」の注意書きを足してよい)
- 本文にも品番・品名・数量の表を貼り、宛名・納品日・合計点数を書く
- 返答の最後の行に `【対応待ち】`

## 3. 承認後に印刷して写す

```bash
cd "C:/ClaudeCode/900.ClaudeCode/納品書発行"
python make_delivery_note.py <受注番号> ... --recipient "…" --print --copy
```

- 見本と同じ引数(納品日も同じ)で流す。日をまたいだら `--date` で見本の日付に合わせる
- `Pages handled: 1` が出たことと、`Get-PrintJob -PrinterName (Get-CimInstance Win32_Printer | ? Default).Name` で待ち行列から消えたことを確かめる
- 報告には標準プリンターの名前(10/27 時点は EPSON PX-S887(普通紙))と、PDF を写した2か所のフルパスを書く
