# line-notify — LINE グループへ、画像つきで状況を知らせる

作業フォルダ: `C:\ClaudeCode\.claude\skills\line-notify`。道具: `make_status_image.py`(画像)/ `line_notify.py`(公開・送信)。

**2026-10-16 寺下さん決定**: LINE で通知するときは、**単純なテキストだけにしない**。
**状況を説明した画像を作り、その公開アドレス(URL)を添えて送る**。受け取る人(社外の端末・スマホ)が URL を押せば画像が見える形にする。
**グループへ送る前に、寺下さん宛の1対1トークで下書きを承認してもらう**(承認は LINE WORKS の承認トークで応答・2026-10-20〜。手順3)。

## 前提(ここを間違えない)

| 項目 | 内容 |
|---|---|
| どの LINE か | グループへの投稿は**通常の LINE**(Messaging API)。**下書きの承認だけは LINE WORKS**(041 relay 経由・2026-10-20〜) |
| 送信者 | ボット **FujiWorks**(`090.LINE業務指示エージェント` が持つ)。グループの全員に見える |
| 画像の渡し方 | LINE は画像を「公開URL」でしか渡せない。ボット経由で画像ファイルは送れない |
| 公開置き場 | `https://pub.sfuji.f5.si/`(Caddy の静的置き場・`900.ClaudeCode/public-share/`・**ログイン不要・一覧表示なし・GET/HEADのみ**) |
| URL の守り方 | 推測されにくい長い乱数ファイル名。**URL を知っている人は誰でも見える**。社内・個人情報の画像は置かない |
| 社内LANの罠 | 社内 LAN からは公開ドメインが引けない(ヘアピンNAT非対応)。`pub.sfuji.f5.si` は **DNS 登録済み**(2026-10-16・TK へ依頼)。新しい公開名を足したときは `/subdomain-add` の手順 |
| グループIDの置き場 | `090.LINE業務指示エージェント/data/line_groups.json`(**Git対象外**)。**グループIDをスキル・メモリ・会話に書かない**(`line_notify.py groups` は先頭と末尾だけ表示) |

## 手順

### 1. 何を伝えるか決め、画像の仕様(JSON)を書く

通知の中身(何をしたか・どこに反映したか・注意点・確認方法)を画像にまとめる。A4 縦 1 枚。
仕様の書き方は `make_status_image.py` の冒頭を見る(見出し・表・変更前後・写真・注意・メモ)。

- **写真は元ファイルから**(例: 削除した写真・残した写真を並べる)。赤枠=削除、緑枠=残す
- 文字は短く。1 ページに収まらないときは**項目を減らす**(道具は収まらないと止まる。小さくして詰めない)
- お客様向けの価格は**税込**で書く。G番号は**商品名を括弧書きで併記**する

```bash
python C:/ClaudeCode/.claude/skills/line-notify/make_status_image.py <spec.json> <out.png>
```

作ったら**画像を自分で開いて確認**する(見切れ・誤字・数字)。

**在庫・数量などの一覧を載せるとき(2026-10-17 迷彩服上下で確定した形)**:
- 数字の並びは文章にせず**表**にする。`sections` に `grid`(`header`・`widths`・`rows`・`stop_rows`)を使い、商品の写真を左に置く(`image`)。**写真は SKU 単位ではなく商品単位で1枚**。`stop_rows` の行は薄い赤(販売停止など)。例は `make_status_image.py` の `grid` 部分と、実例 `.mail_drafts/camo_stock_spec.json`
- **「何から何に変更」は書かない。** 今どうなっているか(現状)だけを載せる(寺下さん指示)
- 商品写真は自社サイトの商品画像(026 の `image_url`、例 `https://seifukunofuji.co.jp/pic-labo/u0147a.jpg`)をスクラッチ領域へ取って使う。ローカルに無い
- 文面は短く。「〜時点の報告をもとに」のような理由の一文は入れない。日付は**見出しの1回だけ**、語は「**更新**」(「現在」だと元からそうだったように読める)。例: `【迷彩服上下】ネット在庫の状況(10/17更新)`
- 文面を変えたら承認コードは作り直し(旧コードは使えない)。画像を作り直したら URL も作り直し、**古い公開ファイルは `public-share/` から削除**する

### 2. 画像を公開してURLを作る

```bash
python C:/ClaudeCode/.claude/skills/line-notify/line_notify.py publish <out.png> --prefix g0964
```

- 乱数つきのファイル名で置き、この端末から自分自身(127.0.0.1)に向けて「HTTP 200・サイズ一致」を確認する
- 画像は元ファイルとは別に、**Downloads と NAS(`\\192.168.1.50\共有スペース\寺下\999.一時ファイル`)にも 1 部コピー**する(成果物の置き場の決まり)
- **寺下さんに、スマホ(モバイル通信または社内 Wi-Fi)で URL を開いて確認してもらう**。開けたと言われるまで送らない

### 3. 寺下さんの1対1トークで承認をもらう(2026-10-16 寺下さん決定・2026-10-20〜 LINE WORKS で承認)

**グループへ送る前に、必ず寺下さん宛の1対1トークへ下書きを送り、寺下さんが承認したものだけを送る。**
(Claude の画面での承認ではなく、トークでの承認。画面では「送った・待っている」を伝えるだけ)

**2026-10-20 運用者決定: 下書きの承認は LINE WORKS の承認トーク**(端末 A の見張り役 a_browser_watch と同じトーク)。
**グループへの投稿そのものは、これまでどおり LINE**(ボット FujiWorks)。LINE で承認する送り方も残してあり、
`900.ClaudeCode/a_browser_common/approval_channel.py` の 1 か所で戻せる。

```bash
python C:/ClaudeCode/.claude/skills/line-notify/line_notify.py request-approval --group <グループ名> --text-file <本文.txt> --url <URL>
```

- **見張り役が止まっていると承認を求めずに止まる**(押されたボタン・文の返信の判定は見張り役が行うため)。
  そのときは `python -m a_browser_watch.cli status`(`C:\ClaudeCode\900.ClaudeCode` で)で状態を見て、運用者に見張り役の起動を頼む
- LINE WORKS の承認トークに、①送信先と**全文**(長ければ (1/3) のように分けて届く。切り詰めない)と画像の URL
  ②「送信する」「中止」のボタン、が届く。**確認コード(6文字)**と本文の確認コード(sha8)が表示される

寺下さんの返信と、その扱い(承認の有効期限は **24時間**・1回だけ有効):

| 寺下さんの操作 | 結果 |
|---|---|
| 「送信する」ボタン / `OK コード` / `コード 承認` | **承認** |
| 「中止」ボタン / `中止 コード` | 中止(送らない。承認の後でも、送る前なら取り消せる) |
| **コード付き**のそれ以外の文章(例: `ABC123 3行目を直して`) | **修正の依頼**として本文ごと記録 |
| コードの無い文 | **無視**(同じトークを remote-control なども使うため。LINE と違い、コードの省略はできない) |

返信を待つ(**バックグラウンドで実行**して、終わったら通知を受ける。ポーリングで画面を占有しない):

```bash
python C:/ClaudeCode/.claude/skills/line-notify/line_notify.py wait-approval <コード> --timeout-min 30
```

終了コード: `0`=承認 / `10`=中止 / `11`=修正の依頼(返信の本文が出る)/ `12`=期限切れ / `13`=時間切れ(まだ待ち。コードは有効)

- 修正の依頼(11): 文面を直して、**もう一度 request-approval からやり直す**(新しいコードになる)。直した旨を寺下さんに伝える
- 中止(10): 送らず、理由を確認
- 時間切れ(13): 待ち続けるか、寺下さんに LINE WORKS の確認を促す(コードは24時間有効)
- 本文を1文字でも変えたら承認は無効(コードと本文の確認コードの組で守っている)

**メンション付きで送るとき(2026-10-19 追加)**: `request-approval` と `send` の両方に `--mention <表示名>` を付ける。
表示名は `090.../data/roster.json` の `displayName` と完全一致(全角スペースも含む。例 `椋田　和`)で1人に決まる必要がある。
先頭に「@表示名 さん」が本物のメンション(textV2)で付く。相手も承認の照合に入るので、承認後に相手を変えると送れない。
**引用返信はできない**(090 が元投稿の quoteToken を保存していないため)。投稿への返事は「13:11の〜」のように文中で示し、投稿者にメンションする。
投稿者は 090 の記録では分からない(名簿は最後の発言グループしか持たない)ので、**寺下さんに聞く**。

### 4. 承認後に、グループへ送る

```bash
python C:/ClaudeCode/.claude/skills/line-notify/line_notify.py send --group <グループ名> --text-file <本文.txt> --url <URL> --approval <コード>            # 確認のみ
python C:/ClaudeCode/.claude/skills/line-notify/line_notify.py send --group <グループ名> --text-file <本文.txt> --url <URL> --approval <コード> --send     # 送信
```

- **承認済み・送信先と本文が承認時と同じ・未使用・期限内**のときだけ送れる(違えば理由を出して止まる)
- 送ったら承認コードは**使用済み**になり、二度は使えない(送信に失敗したら戻る)
- 送ったら **LINE のメッセージID が返る**。寺下さんに、グループの画面で届いたか確認してもらう
- 送信ログ: `090.LINE業務指示エージェント/data/line_notify_log.jsonl`

### 貼られた発言から送信先のトークを探す

運用者が「この発言があるトークへ送って」と発言を貼ったときは、その一部で `line_messages.text` を `LIKE` 検索して `target` を得る（読み取り専用）。
登録名は運用者にクリック形式で聞いてから `register` する（10/19「ハイアップ注文」をこの方法で登録）。

## グループの追加

新しいグループへ送るとき: ボットをグループに招待 → そのグループで誰かが `@FujiWorks` をつけて 1 通投稿 → 090 の受付記録に
グループID が残る(`090.../data/line_agent.db` の `line_tasks.group_id` / `line_messages.target`)。
`line_notify.py register --name 名前 --group-id Cxxxx` で登録する。**グループの人たちに見える投稿になるので、試験投稿は事前にひとこと断る**。
(`@FujiWorks 〜` の投稿は 090 に「受付 #N」の依頼として登録される点に注意。不要なら取り下げる)

### 「あのトークに送りたい」と言われたら: 090 の受付記録で探す(2026-10-17)

ボットが入っているのに一覧(`line_notify.py groups`)に出ないグループは、`090.LINE業務指示エージェント/data/line_agent.db` の
`line_messages`(`target` がグループID・`text`・`received_at` はミリ秒)に**発言が残っている**。
寺下さんが「この投稿があったグループ」と言うときは、その文言で `line_messages.text` を `LIKE` 検索し(**読み取り専用**で開く)、
`target` を取り出して `register` する。**グループIDは画面・会話に出さない**(先頭5文字までなら可)。
名前は寺下さんに聞く(例: 「制服のフジ（役員）」を 2026-10-17 に登録)。登録しただけではグループには何も見えない。

## やってはいけないこと

- **1対1トークでの承認なしの送信**、文面を承認後に変えて送ること(道具が止める)
- **グループID・トークン・PIN を会話・スキル・メモリに書く**(`090/.env`・`065.../.env` の値を表示しない)
- 画像を**社外のサービス**にアップロードして URL を作る(社内画像が社外に残る)
- 個人情報・原価・顧客名の入った画像を公開置き場に置く
- 公開置き場の README や一覧を置く(`public-share/` は `.gitignore` で中身を Git 対象外にしてある)
