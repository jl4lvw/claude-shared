# /fba-replenish — FBA へ補充する商品と数を決める

**読み取りだけのスキル。** 022 の在庫・カート・必要数・7S専用の印は変えない。
カート(ピッキングリスト・7S カート)はブラウザの中にだけ保存されるので、Claude からは入れられない。
入れるのは運用者が PWA で行う。

## 考え方(2026-10-28 運用者と決定)

- **機械の判定は「候補の洗い出し」。送る数は Claude が一件ずつ判断して決める**
- 機械の判定の本体は `022.Amazon在庫PWA/pwa/picking-select.js` の `pickReplenish`(PWA の「🚚 FBA補充」タブと同じ)。
  **機械の判定はこのスキルの中に書き直さない**(PWA とずれるため)。変えるときは picking-select.js とそのテストを直す
- Claude が判断するのは 4 つ: **送る数の増減** / **B を送るか** / **補充元と 7S に残す数** / **送らない商品**
- 納品にかかる日数は **7 日**(`--lead-days` で変えられる)

### 機械の判定(候補の洗い出し)

| 区分 | 条件 | 機械の数 |
|---|---|---|
| A 必ず補充 | 30日売上 × 1.0 − (FBA在庫 + 入荷中) > 0 | 売上ベースの不足 |
| B 要確認 | A でなく、FBA必要数 − (FBA在庫 + 入荷中) > 0 | 必要数ベースの不足 |
| 送れない | 7S専用で 7S在庫(− 1 個)が足りない | 0 |
| 準A(材料だけ) | 機械では対象外だが、FBA在庫+入荷中 < 30日売上の (30 + 納品日数) 日分 | 0 |

- 補充元: 「7S専用」の印(DB v61 `source_7s_only`)があれば 7S、無ければ本店。本店の在庫数は見ない(大半が未入力)
- 対象外: 親SKU・販売終了・手動で除外・Disabled・2SKU の LCL役・FBA運用でないもの
- B のうち、30日売上も「昨年この先30日」の売上も 0 のものは、一件ずつ見ずに一括で送らない

## 手順

### 1. 候補と材料を出す

```bash
cd C:/ClaudeCode && python .claude/skills/fba-replenish/fba_replenish.py
```

- 本番の 022 (`http://127.0.0.1:8090/inventory/all`) を GET で読み、売上の履歴は本番 DB を**読み取り専用**で開く
- 出力は `C:/tmp-ai/fba_replenish/<日時>/`:
  - `report.md` 機械の判定(PWA のタブと同じ結果)
  - `materials.md` / `materials.json` **一件ずつ判断するための表**(作業用。本文に貼らない)
  - `cart_import_hq_machine.json` 機械の数のままの本店分(参考)

### 2. 一件ずつ判断する

`materials.md` を読み、全行について数・補充元・理由を決める。目安の列は
「30日売上の1日あたり × (30 + 納品日数) − (FBA在庫 + 入荷中)」。ここから次の目安で増減する。

| 見るもの | 判断の目安 |
|---|---|
| 7日・30日・90日の売上 | 直近 7 日が 30 日の割合の 2 倍近く伸び、90 日にも売上があれば増やす(30日売上の 1.5 倍まで)。90 日の売上がこの 30 日とほぼ同じ(急に売れただけ)なら目安どおり。今月だけ 90 日の平均の 2 倍を超えるなら、平均と合わせて控えめに |
| 品目の季節 | 秋冬はパーカーを 3 割ほど増やす。Tシャツは夏より落ちる時期なので増やさない(春夏は逆) |
| 昨年この先30日 | 昨年のこれからの時期に多く売れていれば増やす(季節もの)。「—」は注文明細が無い期間(2026-04 より前)なので使わない |
| もつ日数 | 納品日数(7日)より短いものは優先して送る |
| 設定数が多すぎる疑い(B) | 売上に合わない設定数。売上の目安まで減らすか送らない。設定数の見直し候補として報告する |
| 7S在庫(入荷待ち) | 7S から送るときは FBM 用に残す。売れ筋は 2 個以上残してよい。入荷待ちがあれば残しを減らしてよい |
| 補充元 | 「7S専用」の印に従うのが基本。印が無くても本店在庫 0 と入力済みで 7S にあるものは 7S からにしてよい(報告で印を付けるか聞く) |
| 送らない | 売上がほぼ止まっている・切り替えや終了が近いと思われるもの。判断がつかないものは 0 にして「要確認」と理由に書く |

決めたら出力フォルダに `decisions.json` を書く(**`materials.md` の全行を書く**。送らないものは qty 0):

```json
{"items": [
  {"sku": "FUJI-G1234-...", "qty": 6, "source": "hq", "reason": "直近7日が伸びているので目安より+2"},
  {"sku": "FUJI-G5678-...", "qty": 0, "source": "hq", "reason": "設定数が多すぎる疑い・売上は月1個"}
]}
```

- 機械の数と違う数にしたときは理由が必須(同じなら空でよい)
- 理由は短く、運用者が読んで分かる言葉で書く

### 3. 最終の表と取り込み JSON を作る

```bash
cd C:/ClaudeCode && python .claude/skills/fba-replenish/fba_decide.py --dir C:/tmp-ai/fba_replenish/<日時>
```

- 検査(全行そろっているか・7S在庫を超えていないか・理由の有無など)に当たると、何も書かずに止まる。直して出し直す
- 通ると `decision_report.md`(最終の表)と `cart_import_hq.json`(本店分・mode replace)を書く

### 4. 本文で報告する

`decision_report.md` の内容を**本文に貼る**(ファイルを指すだけにしない)。商品名は表にあるので、G番号だけで書かない。
あわせて触れること:

- B で「設定数が多すぎる疑い」の件数(必要数の見直し候補)
- 「送れない」がある → 7S への補充(発注)が必要
- 補充元が「7S専用」の印と違うもの → 印を付け外すか運用者に確かめる
- 「要確認」と書いた商品
- `⚠️ サーバーが「7S専用」の印にまだ対応していません` と出たら、022 サーバーが v61 前の版

### 5. カートへ入れてもらう

運用者に案内する(Claude はやらない):

1. `https://sfuji.f5.si/amzinv/` → ピッキングリストの「📥 JSON取り込み」に `cart_import_hq.json` の中身(フルパスで示す)を貼る
2. 7S から送る分は、表の数を 7S カートへ入れる
3. PWA の「🎯 ピッキング対象選定」→「🚚 FBA補充」タブは機械の判定のままなので、数は表の方に合わせる

その後の FBA 納品は `/amz-inbound`。

## 7S専用の印

- 本店に置かず 7S にだけ在庫がある商品に付ける。付け外しは PWA の FBA補充タブの各行のボタン、
  または `PATCH /inventory/{sku}/source-7s-only` `{"source_7s_only": true|false}`(Origin 検査のみ・PIN なし)
- Claude が API で付けるのは運用者が商品を指定して頼んだときだけ(書き込みなので、付ける一覧を見せて承認を得てから)
