# /rakuten-merumaga-flow — 検査 → 原稿 → 下書き登録（ラッパー）

メルマガ作業を、次の順に 1 本で進める。**各段階が通ったときだけ、次へ進む。**

```
① 原稿の取得（/rakuten-merumaga 手順 1〜3）   メルマガエディタ → 貼り付け用タグ → ローカル保存
② 内容のチェック（手順 6）                    リンク切れ・説明違い・欠品 …… エラーなら終了／警告はユーザーに選ばせる
③ 原稿作り                                    HTML 原稿・テキスト版・携帯用テキスト（5,000 文字以内）
④ 下書き登録の申請                            端末 A へ JSON を relay で送る（A が RMS に「下書き」を保存）
⑤ 結果の確認                                  A からの返信（下書き ID・照合結果）を報告
```

呼び出し側のスキル（それぞれ単独でも使える）:
- `/rakuten-merumaga` … ①②③の部品（`C:\ClaudeCode\.claude\skills\rakuten-merumaga\`）
- 端末 A の RMS 下書き登録 … ④（A の `rakuten_login\mail_draft\`。README 参照）

## 🚨 絶対ルール

1. **配信・配信予約・送信・テスト送信・配信日時の設定は、しない。** 下書き保存まで。配信日時・対象の設定は、運用者が RMS で行う。
2. **RMS の画面操作は、端末 A だけで行う**（ブラウザは A の `rakuten_login` の専用プロファイル 1 つに固定）。TK では RMS にログインしない・パスワードの入力や貼り付けをしない。
3. **メルマガ（テンプレート）の修正はしない。** 検査の指摘は、報告して終わる（修正は別担当者の仕事）。
4. **リンク検査のエラー（載っている商品がすべて販売不可）は必ず止める。** 警告は、内容を見せて、ユーザーに「続行／中止」を選ばせる。
5. **携帯用テキストが 5,000 文字を超えたら、勝手に削らず止める**（RMS の画面の制限と同じ。超過量と削る候補を報告）。
6. **失敗した申請は、自動で再申請しない。** 原因を報告して、ユーザーに聞く。
7. 質問は最初にまとめて聞く（下の「最初の質問」）。席を外されても止まらないように、途中の質問は「警告の続行確認」だけにする。

## 最初の質問（ブラウザ操作より前・ログイン後の一覧が出た時点で 1 回だけ）

1. **メルマガエディタに入って、候補（更新が 5 日以内）を取得する**（`/rakuten-merumaga` の手順 1〜2。ここまでは質問なしで進める）。0 件なら「5 日以内の更新はありません」と報告して終了。
2. **AskUserQuestion で、次を 1 回にまとめて聞く**（候補の取得後にしか分からないので、ここで聞く）:
   - どのテンプレートか（候補の名前と更新日時。1 件でも確認する）
   - **HTML メールの件名**（担当者が LINE で指示した文字列。私は LINE を読めないので、ユーザーが入力する。呼び出し時に「件名: …」と書かれていれば、聞かない）
3. 回答後は、**警告の続行確認以外では止まらず**に、④の申請の送信まで進める。

## 手順

### ① 原稿の取得
`/rakuten-merumaga` の手順 3 のとおり（編集 → 次へ → 「貼付用タグをコピー」→「タグをコピーする」→ `save_clipboard_tag.py --expect <画面の文字数>`）。保存先 `C:\ClaudeCode\900.ClaudeCode\000.tmp\merumaga_tag_YYYYMMDD_HHMM.txt`。
- ⚠ エディタを開くと、テンプレートの「更新日時」が変わる（内容は変わらない）。タグの取得に必要な 1 回だけ開く。
- 編集画面は、最後に必ず一覧へ戻る（保存しない）。

### ② 内容のチェック
```
python ".claude/skills/rakuten-merumaga/scripts/check_mail_links.py" "<タグ.txt>" --json "000.tmp/check_<日時>.json"
```
| 終了コード | 意味 | 動き |
|---|---|---|
| 2 | エラー（全商品が販売不可） | **止める**。理由を報告して終了 |
| 1 | 警告あり | 警告を一覧にして見せ、AskUserQuestion で「続行／中止」を選ばせる（欠品・リンク切れ・説明違い・0 件検索など） |
| 0 | 問題なし | そのまま③へ |

- 中止が選ばれたら、指摘をまとめて報告して終了（メルマガは直さない）。
- 続行が選ばれたら、「警告 N 件を承知のうえで続行」を台帳（ctx）の STATE に 1 行残す。

### ③ 原稿作り + ④ 申請 JSON の作成
```
python ".claude/skills/rakuten-merumaga-flow/scripts/build_draft_request.py" --tag "<タグ.txt>" --subject "<HTML メールの件名>" --template-name "<テンプレート名>" --purpose "<目的>" --out "000.tmp/draft_request_<日時>.json"
```
- 目的の例: `--purpose "10/22 配信の楽天メルマガ(秋の新作 T シャツ)を RMS の下書きに登録し、配信の準備をするため"`
- **purpose(目的)は必須。何のための操作か(誰に何を知らせる・何を補充する等)を 6〜120 字で書く。承認の画面・LINE WORKS・電話の音声案内で運用者に示す。電話の文は外部の音声サービス(Microsoft)へ送るので、人名・住所・電話番号・メールアドレス・お客様名は書かない**（2026-10-21 運用者決定。申請 JSON の `"purpose"` に入る。無い・短い・長いと終了コード 2 で保存しない。A の enqueue でも同じ検査をする）
- HTML 原稿＝貼り付け用タグそのもの。**テキスト版（`html.text_body`）と携帯用テキスト（`mobile_text.body`）は、同じ変換**（`html_to_mobile_text.py`）で作る（HTML メールは RMS で「テキスト部分の本文」が必須のため）。
- 検査（違反は終了コード 2・保存しない）: HTML 100 KB 以下／件名 255 バイト以下（半角換算）／携帯用テキスト **5,000 文字以内**（改行を 2 文字と数えた値）。
- 携帯用テキストが超過したら、止めて報告（超過量・URL が占める分・商品点数）。削り方は、ユーザーに相談する。
- モバイルの件名は A が固定値（『【制服のフジ楽天市場店通信】』）を持つ。申請では指定しない。
- 携帯用テキストとテキスト版は、**Downloads と NAS の両方**にも置く（テキスト成果物のルール。ファイル名 `merumaga_mobile_YYYYMMDD.txt`）。

### ④ A へ申請を送る
```
python ".claude/skills/relay/scripts/relay_client.py" send --to A --type task --reserve --file "000.tmp/draft_request_<日時>.json" "【TK→A RMS下書き申請】<テンプレート名>。添付の JSON を enqueue してください(HTML+モバイルテキストの下書き)。配信・予約・送信は不要。実行は運用者が立ち会えるときで可。"
```
- `--to A`（A=本人端末。RC は長張さん端末で別）。送信後は、**スレッドの予約を必ず解放**（`release`）するか、待つなら `wait` で受け取る。
- A は「enqueue → 運用者が立ち会えるときに run → 結果を relay で返信」。**すぐには返らない**ことがある。

### ⑤ 結果の確認
- A の返信（`status` = queued / running / done / failed / needs_human、種別ごとの `rmail_id`・件名・文字数・`match`（開き直しの照合）・スクリーンショット）を表にして報告する。
- `done` かつ `match` が両方「一致」なら、「下書きができました。配信日時・対象の設定と配信は、RMS（R-Mail の『送信一覧』）で運用者が行ってください」と伝える。
- `failed`／`needs_human`／`already_exists` は、画面の文言をそのまま報告して止まる（自動で再申請しない）。
- 受け取った relay メッセージは `done <id>` で処理済みにする。
