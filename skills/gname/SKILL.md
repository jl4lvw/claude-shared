# gname — G番号は商品名つきで書く

運用者は G番号を暗記していない。番号だけでは何の商品か判断できない。
人が読む文面に G番号を書くときは、**常にこの形式**にする。

```
G1447(護衛艦いずもドライTシャツネイビー)
```

## ルール(必須)

1. **G番号は単独で書かない。** 「G番号(商品名)」の形で、運用者が判断できる商品名を併記する。サイズ・素材・カラー等の括弧を落とさない(落とすと別商品・別行と区別できない)。
2. **商品名は推測しない。** 取得元を確認できるものから取る(下記「取得元の優先順」)。取れなければ「G1234(商品名未確認)」と明記する。その状態で運用者に二択などの判断を求めない。まず調べる。
3. **すべての文面で適用する。** 選択肢・質問・表・箇条書き・件名の要約・relay 本文の転記。relay 本文に商品名が無い品番は、こちらで調べた商品名を補って併記する。
4. **2回目以降の言及でも、判断を求める文面では毎回併記する。** 省略してよいのは、同じ表の中で既に併記した直後の同一品番の繰り返しだけ。
5. **商品名を取れない処理役・待ち受け(サブエージェント)に渡す依頼文にも、この規則を書き込む。** 報告は商品名つきで返すよう指示する。

## 取得元の優先順

1. 店頭のライブ照会: `https://seifukunofuji.co.jp/SHOP/<G番号>.html` の `<title>`(UTF-8 でデコードする。cp932 だと文字化けする)。読み取りのみ。
2. 商品DB・発注履歴: `017.Tシャツなどの注文\lookup_product.py <G番号>`(`product_db.json` の件名候補。カラーなど発注時のバリエーションが入っていることがある)。
3. 023 商品マスタ(A端末側)。記録値は実態と食い違うことがあるので、ライブ照会と食い違えば店頭を優先し、「記録は〜」と書き分ける。

店頭が 404(非表示)なら「非表示のため店頭では取得不可」と書き、2 以降の取得元を明記して使う。どの取得元から取ったかは、運用者に聞かれたら答えられるようにしておく。

注意: 店頭タイトルにはサイズ・発注時のカラーが入らないことがある。判断に色・サイズが要る場面(発注、畳み方、数量など)では、`lookup_product.py` の件名候補などから括弧で補う。例: `G1447(護衛艦いずもドライTシャツネイビー / 発注名: Tシャツ いずも Type2(ネイビー))`。

## 表示例

悪い例(番号だけ):

> G1447 は番号1でよいですか。

良い例:

> G1447(護衛艦いずもドライTシャツネイビー)は番号1でよいですか。

表の例:

| 品番 | 商品名 |
|---|---|
| G1440 | 練習艦はたかぜ TシャツType1[黒] |
| G1691 | 練習艦しまかぜ Tシャツネイビー |

選択肢の例(悪い→良い):

> 1. G0864 を先に発注 / 2. G0865 を先に発注
> 1. G0864(t-shirts(男の修行))を先に発注 / 2. G0865(t-shirts(やってみせ))を先に発注

商品名が取れないとき:

> G1234(商品名未確認)について、店頭と商品DBを確認しましたが見つかりませんでした。品名を教えてください。

## 適用しない場面

- 客先・業者向けメールには G番号自体を書かない(`feedback_order_mail_rules` 参照)。本スキルは社内向けの報告・確認・承認依頼・relay が対象。
- コード・ファイル名・コマンド引数など、機械が読む場所の G番号はそのままでよい。
