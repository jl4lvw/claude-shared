# price-revision-jr — 卸売先への価格改定通知

作業フォルダ: `C:\ClaudeCode\063.価格改定通知`(相対パスは全てここ基準)。
2026-10-07、呉駅おみやげ街道9品の改定を実際に一件流して確立。以前は別の担当者が送っていた作業で、今は寺下さんが担当。

## 全体の流れ

```
1 改定リストを受け取る(写真共有→/img など)
2 読み取り→検算(税抜100円単位)→現行価格を台帳と照合
3 商品を台帳(jr_catalog.json)で特定。無ければ先方の書類でJAN等を調べて add
4 ユーザーに確認(下の「確認する事項」)
5 依頼書を作る: make_revision_forms.py make → PDF実測・目視
6 PDFを Downloads へコピー → 紙で検査(print_forms.py)→ 修正があれば 5 へ
7 メール: /mail-send を呼ぶ(アーティファクト承認→下書き。送信は人)
8 送信後: 送信済みを確認 → 04_提出済へ整理 → record で台帳更新 → README
```

## 守ること(省略禁止)

- **送信は寺下さんが手動**。Claude は下書きを開くまで。アーティファクト承認の前に EML を作らない(`/mail-send` の手順どおり)
- **変更後の価格は「税抜が100円単位+消費税10%」**。合わなければ読み違いを疑って質問する(実例: 874円→770円、3,416円→3,410円)。スクリプトも `エラー` で止める
- **現行価格は台帳 `current_incl` と照合**。メモの現行と食い違ったら、先方の登録書類(下記)で確かめてから進める。2,300円・2,981円のように税抜が割り切れない現行もあるが、台帳側が正しいことがある
- 外部への書込(メール送信)は承認を得てから。**印刷も、実寸(noscale)でプリンター名を確認して**行う

## 1. 受け取る

改定リストはスマホの写真(`/img` で取り出す)・メール・Excelなど。写真の手書きは読み違いが出る。**転記表を作ってユーザーに見せ、現行→変更後の両方を確認**する。

- 「角型」と「舟型」、「青」と「水色」のように、書類上の名前と手書きが違うことがある。台帳(`python scripts/make_revision_forms.py show`)の商品名と突き合わせる
- 対象外の行(変更なし)を取り違えない。メモにある数字が「現行と同じ」なら対象外

## 2. 商品を特定する

1. `python scripts/make_revision_forms.py show` で台帳の一覧を見る(JAN・商品名・現行・サイズ)
2. 台帳にある商品は、そのまま `JAN=変更後の税込売価` を渡せる
3. 台帳に無い商品は、先方の書類を一次資料にして JAN・商品名・半角カナ・サイズを調べ、`add` する

先方の書類の置き場(LAN・端末Aから。UNCはPowerShell経由が安全):
`\\192.168.1.50\共有スペース\[マリングッズ卸先]\JRサービスネット広島\`

| フォルダ | 中身 |
|---|---|
| `価格改定\` | 過去の価格改定の提出書類(2026年1月のミニマスコットが最新の手本) |
| `登録時の書類\商品登録\` | 商品登録時の書類(2020〜2025年)。JAN・サイズ・カナの出所 |

- JAN は本文・書類を **バイト列で検索**するのが速い(`4562210…` の13桁。xlsx は zip 内の xml/sharedStrings を grep)
- **023商品マスタにJANは無い**(楽天・Eストア用)。ここで探さない

## 4. 依頼書を作る

```bash
cd C:\ClaudeCode\063.価格改定通知\scripts
python make_revision_forms.py make --check 4562210666866=990 4562210664237=3410   # まず様式のチェックだけ
python make_revision_forms.py make 4562210666866=990 4562210664237=3410           # 03_作成中\提出用 へ出力
```

- 出力: 商品ごとに PDF と xlsx、メール本文 `mail_body.txt`。**すべて「送付OK」(黄0・赤0)**になるまで直す
- Excel(COM)が必須。原本のテンプレートは読み取り専用で開くので変わらない
- **作ったPDFは必ず目で見る**(提出日・JAN・金額・商品名・印影)。PDFを画像にして1枚にまとめると速い
- **印影は紙の上で直径18mm**。様式がA4に縮小されるので、PDFを実測する(丸印の赤い領域の幅が17.9mm前後。`STAMP_SIZE_PT` を変えたら必ず実測し直す)。透明背景のままだと枠の「印」の文字が透けるので、白地版 `02_客先フォーマット\社印\Fuji_Maru_白地.png` を使う

## 5. 紙で検査する

1. PDF を `Downloads\価格改定PDF_<日付>\` へコピー(ユーザーが画面で見る用)
2. `python scripts/print_forms.py`(既定プリンターへ実寸で印刷。`--printer` で指定可)。終了コードとキューを見る
3. 修正があれば 4 からやり直す。**直したら Downloads も、提出用の元PDFと入れ替える**(ハッシュで一致を確認)
4. 旧版を印刷してしまったら、ユーザーに破棄を頼む

## 罠(実際に踏んだもの)

| 罠 | 対処 |
|---|---|
| Excel に `datetime` を渡すと提出日が1日前になる | シリアル値(日数)で渡す(実装済み) |
| 旧印影(角印)がテンプレートに入っている | 丸印へ差し替える(`swap_stamp`、実装済み) |
| 印影が小さい | 18mm=紙の上の寸法。縮小率を見込んで実測で合わせる |
| 印刷が `fit` だと縮む | `noscale`(`print_forms.py` は実装済み) |
| Bash の heredoc で UNC の `\\` が `\` になる | UNC は PowerShell か、`chr(92)` で組む |
| 手書きの読み違い(874/770、3416/3410、角型/舟型、青/水色) | 税抜100円単位の検算で気づける。聞いて確かめる |
| メールの `Cc:` 行を本文にも書く習慣 | `mail_body.txt` が `MAIL_CC_NAMES` で出す。Cc を変えたら定数も変える |
| 旧版の下書きが Thunderbird に残る | 作り直すたびに「古い下書きは破棄」とユーザーへ伝える |
